# 36｜图片生成 3D 资产后，怎样检查与导出

生成出 GLB 或 OBJ，只证明取得了某种文件，不等于资产能直接进入游戏、网页或制造流程。本篇以通用 glTF/GLB 交付为例，检查结构、纹理、尺度与外观；不承诺生成资产拥有可制造的拓扑或可动画绑定。

## 先定义目标用途

网页展示通常关注加载体积、纹理和渲染效果；游戏还需要面数、材质数量、碰撞体和性能约束；3D 打印则要另查封闭性、厚度与真实尺寸。记录目标工具和格式，避免拿一张预览图当成网格交付。

> 用 Atlas 从我的获授权参考图生成一个用于网页展示的 3D 资产。先确认模型的 3D 能力、输入与输出格式，说明不可见背面可能被猜测，确认后生成一次。交付真实网格、纹理与预览，并检查加载、尺度和材质；不声称已经通过制造或游戏性能验证。

## 生成与产物选择

独立 MCP 中 3D 归入 Image 类型，并通过 `atlas_generate_image` 路线处理；CLI 则仅在当前版本和账户目录支持时使用 3d 路径。先读模型详情，确认是 image-to-3D 还是 text-to-3D，不能把普通图片输出当成模型文件。

```bash
atlas models list --type 3d --json
MODEL='替换为当前账户可用的3D模型ID'
atlas models get "$MODEL" --json
```

上传参考与生成需要明确授权。回执中可能同时有 GLB、ZIP 和渲染预览；逐一记录真实类型，不只下载第一项。ZIP 解包前审查目录，拒绝绝对路径、上级目录穿越、符号链接和异常大文件；不要执行包内脚本。

## 结构校验与本地导入

Khronos glTF Validator 可检查 glTF/GLB 的规范问题。使用官方工具，按其说明验证并保存报告；不把商业保密模型上传到未经批准的服务。规范错误与警告分开检查，验证器通过并不代表几何正确、材质好看或运行性能达标。

在已安装的可信 3D 编辑器中导入实际资产。Blender 等工具的导入位置与版本有关，按当前安装界面选择 glTF/GLB 导入，不复制未知来源的自动执行脚本。旋转观察正面、侧面和背面，检查缺面、法线、透明材质、贴图丢失、比例与中心位置。

## 处理与重新导出

先保存原始生成文件，再在副本上处理多余网格、材质和尺度。单张图看不到的背面可能是生成的假设，重要物体应补充真实参考或人工重建。调整面数、压缩纹理、改变单位后，重新导入导出文件，避免导出选项漏掉贴图或对象。

网页验收需在目标渲染器加载，检查旋转、缩放、移动端内存和透明效果。不要用桌面编辑器预览正常来证明所有终端可用。模型转换为另一个格式也不能通过改后缀完成。

## 最终交付

交付原始资产、处理后的发布资产、纹理（若外置）、预览、校验报告和单位/面数/修改记录。使用本包 manifest 对专用交付目录建立摘要；保留未通过项，例如“背面细节未核实”“未绑定骨骼”“未测试 3D 打印”。结构或导出失败先在本地修复，不默认再调用生成模型。
