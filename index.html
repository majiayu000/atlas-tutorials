01｜把 Atlas 接入你的 Agent，先不花钱生成

你已经有自己的 Agent，希望它能调用 Atlas。第一步只验证三件事：终端能找到 CLI，当前登录状态清楚，Agent 能读到 Atlas 的操作指南。完成配置不需要先生成一张测试图片。

本文适合本地有终端能力的 Agent。没有终端访问能力的网页宿主，不能照搬这条路径。MCP 用户参见 03，不必同时安装两条执行路线。

状态：正文已完成；未执行线上付费生成或宿主实连。依据：S1 / S2 / S3。本地测试范围见 验证报告。

先确认安装

已有 Atlas 时先检查，不要覆盖现有配置：

atlas version --json
atlas --help

没有安装且已有 Node.js/npm 的环境，可以采用公开包：

npm install -g atlascloud-cli
atlas version --json

没有 npm 的环境，使用公开 CLI 仓库给出的系统安装器；不要为了一个安装步骤下载来历不明的脚本。安装成功后如果 Agent 仍报告找不到命令，确认 Agent 启动时使用的 PATH，并重新启动对应进程。

检查认证，不要把密钥贴给 Agent

atlas auth status --json

这里检查的是本地认证状态。logged_in 表示本地访问令牌尚未过期，不保证某个供应商模型一定接受调用。遇到 not_logged_in、expired 或 refresh_required，按当前 CLI 提示完成登录：

atlas auth login

保留用户原有的账户和环境。不要因为供应商错误，替用户切换开发环境、其他账户或认证方式。需要诊断时使用：

atlas doctor --json

诊断结果也可能包含账户或机器信息。发布 issue 前只保留解决问题所需的字段，不上传密钥或完整凭据文件。

安装一个适合当前宿主的 Skill 入口

只选当前 Agent 对应的一条：

atlas skills install --agent claude

或者：

atlas skills install --agent codex

项目级目录可以显式指定，路径须与你的宿主实际配置相符：

atlas skills install --dir .claude/skills

这只是将 Atlas 入口写到相应的 Skill 目录，不会自动替其他客户端完成 MCP 配置。出现已有文件冲突时先看差异，不要删除别人的 Skill。随后启动新会话，再验证：

atlas skills read atlas --raw

如果当前二进制没有这些命令，按自己的安装渠道更新，再重新检查；不要把教程中的命令名改成猜测的近义词。

发给 Agent 的第一句话

请检查我的 Atlas 是否可以使用。先确认 CLI 版本、当前本地认证状态和 Atlas Skill 是否可读；需要登录时由我完成授权。保留我的账户与环境，不读取或显示令牌，不上传文件，不调用付费模型。最后告诉我已验证的部分和仍未验证的部分。

怎样算完成

能够确认版本；本地认证状态清楚；Skill 正文可读；Agent 能解释下一次任务会先查询模型能力。到这里仍然没有证明任何模型成功生成过内容，这很正常。下一篇再完成第一张图片。

常见误区是把“Skill 已安装”“CLI 已登录”“模型可用”当成同一个状态。记录三者，可以少走很多排错弯路。

02｜生成第一张图片，同时保存任务回执

本教程的目标是一张实际可打开的图片，以及能再次查询它的任务 ID。演示主题是网站的抽象配图，不使用参考文件，也不要求模型生成标题文字。

准备好 Atlas CLI、可用账户和 Python 3.9+。从本教程包根目录执行 Bash 示例。所有模型 ID 必须从当前目录复制；本教程不预设某个旧 ID 永久可用。

状态：正文已完成；未执行线上付费生成或宿主实连。依据：S1 / S2 / S3。本地测试范围见 验证报告。

给 Agent 的任务说明

用 Atlas 为一个开发者工具网站生成一张抽象配图，画面有清楚的主体与留白，不包含文字和 logo。先查询支持文本生成图片的模型，给出一个选择及依据，核对参数并估价。只预览，不提交，等我确认后生成一张。保存原任务 ID，交付时给出真实文件；等待超时不要重新生成。

手动执行：先选模型

set -euo pipefail
atlas version --json
atlas auth status --json
atlas models list --type image --json

选择支持文本生成图片的模型，确认所需参数。不要选择必须带参考图的编辑模型：

MODEL='替换为当前可用的真实模型ID'
atlas models get "$MODEL" --json
atlas skills read atlas/references/image.md --raw

如果 schema 需要 prompt 以外的字段，应先补齐。例子里的主题没有尺寸硬约束，可以使用该模型的默认尺寸；需要具体画幅时，再按模型实际支持的字段和取值填写。

预览与估价使用同一组输入

PROMPT='Abstract visual for a developer tool website. One clear sculptural subject, soft studio lighting, ample clean negative space. No text, no letters, no logos.'
INPUT=(-p "$PROMPT")

# 有其他必填字段时，先按真实 schema 加入 INPUT，再执行下面两条。
# 例如语法是 INPUT+=(--param "字段名=实际值")，不要原样使用这个占位表达。
atlas generate image "$MODEL" "${INPUT[@]}" --explain --json
atlas generate cost image "$MODEL" "${INPUT[@]}" --json

检查预览里的模型、输入与默认值。估价失败或价格不明确时，不要拿零费用代替未知；先说明不确定性。本文把“确认后执行一张”作为示范授权边界，它不是服务端硬额度设置。

用户确认后，提交一次并保留回执

下方会产生真实模型调用费用。先确认数量与配置符合授权，再执行。目录只在第一次创建；出现异常后不要从创建新目录开始重新跑一遍。

mkdir -p tutorial-output
RUN_DIR=$(mktemp -d './tutorial-output/image-XXXXXX')
printf '%s\n' "$MODEL" > "$RUN_DIR/model.txt"
printf '%s\n' "$PROMPT" > "$RUN_DIR/prompt.txt"
printf '本次记录目录：%s\n' "$RUN_DIR"

if [ -e "$RUN_DIR/submit.json" ]; then
  printf '%s\n' '已有提交记录，请查询原任务，不要再次提交。' >&2
  exit 1
fi

if ! atlas generate image "$MODEL" "${INPUT[@]}" --no-wait --json > "$RUN_DIR/submit.json"; then
  printf '%s\n' '提交返回异常。保留回执，先核对是否受理，不要自动重试生成。' >&2
  exit 1
fi

PREDICTION_ID=$(python3 scripts/receipt_id.py "$RUN_DIR/submit.json")
printf '%s\n' "$PREDICTION_ID" > "$RUN_DIR/prediction-id.txt"
printf '任务 ID：%s\n' "$PREDICTION_ID"

辅助脚本只从已知 CLI 字段读取 ID；不把状态为 processing 的任务当成完成，也不会自行发网络请求。空回执、损坏 JSON 或缺少 ID 都需要核对，不能证明请求没有受理。上面的本地文件检查也不是跨进程幂等保证。

等待和交付

atlas generate wait "$PREDICTION_ID" --timeout 10m --json > "$RUN_DIR/result.json"

10m 是这次本地等待的上限，不是视频或图片预计完成时间。等待返回后同时看命令退出状态和 JSON 中的 prediction 状态。结果处于处理中时，继续查询同一个 ID。

完成后检查 outputs 与 saved_files。未指定输出路径时，让 CLI 使用实际媒体类型选择扩展名；不要看到 URL 末尾就猜本地文件名。打开 saved_files 中的真实路径，确认文件非空并检查画面。不具备图片查看能力时，应明确“只验证了文件，未做视觉检查”。

最终交付说明至少写清：模型 ID、任务 ID、生成状态、真实文件路径、画面是否已经人工或视觉检查。远程完成但没有本地文件时，进入 43 恢复教程。

建议将生成目录加入项目已有的 .gitignore。不要覆盖整个文件，只追加所需规则。prompt、文件路径、输出 URL 和模型回执也可能包含业务信息，应与密钥一样谨慎审查后再分享。

03｜本地 MCP 接入：先看工具和请求，再生成

本教程使用公开 atlascloud-mcp 包的本地 stdio 路线。它与 CLI 源码里的实验性 atlas-mcp 二进制、插件里的远程 OAuth 服务不是同一条安装路径。只需要本地 MCP 时，不必再为它编译 Go 源码。

准备一个能启动本地 MCP 进程的宿主、该包所需 Node.js 环境，以及自己的 Atlas API key。包 README 当前写 Node.js >=18；正式发布教程时仍要核对当前包 engines 和团队支持的 Node.js 版本，不要据此建议使用已停止维护的旧版本。

状态：正文已完成；未执行线上付费生成或宿主实连。依据：S1 / S2 / S3。本地测试范围见 验证报告。

先决定密钥放在哪里

不要把真实 API key 写进教程、公共配置、截图或 Agent 对话。使用宿主提供的密钥配置，或让从终端启动的宿主继承环境变量。下面是在 Bash 中输入环境变量的一种方式，不会把密钥正文写进这条 Shell 命令：

read -r -s -p 'Atlas API key: ' ATLASCLOUD_API_KEY
printf '\n'
export ATLASCLOUD_API_KEY

这不是系统密钥链，环境变量仍可能被有权限的进程访问。GUI 中启动的宿主也未必继承你刚刚设置的终端环境；连接失败时应核对进程实际获取密钥的方式，不要不停创建新 key。

  }
}

将这段合并进宿主的配置，不要覆盖原有其他 MCP。它没有包含密钥：你必须通过宿主支持的安全方式提供 ATLASCLOUD_API_KEY。如果宿主使用不同结构，按它的实际格式填写同一进程命令，不能直接复制整段。

团队部署应在联调通过后固定已验证的 npm 包版本，避免每次连接都依赖浮动版本；记录版本，但不要凭空填一个版本号。

第一条消息只做发现

检查已连接的 atlascloud MCP。先列出实际可用的工具，再查询文本生成图片的模型，并读取一个候选模型的参数 schema。不要调用聊天模型，不上传文件，不生成媒体，不更换我的账户或凭据。

期望看到可调用的模型发现与详情工具，例如 atlas_list_models 和 atlas_get_model_info。必须以当前连接返回的工具 schema 为准，不能因为 README 出现过一个名字，就假定当前服务一定提供它。

第二条消息只预览

按刚才选定的文本生图模型，准备一张无文字的抽象网站配图。使用生成工具的 dry_run 预览完整请求，不提交。解释模型、必填参数和默认值；如果没有可靠价格信息，明确说估价仍未知。

在实际工具 schema 确认存在这些字段后，图像生成请求形态可以是：

{
  "model": "替换为已查询的真实模型ID",
  "params": {
    "prompt": "An abstract visual for a developer tool website, no text."
  },
  "dry_run": true
}

这只是调用结构示意，params 必须补上该模型当前必填项。dry_run 的作用是展示将提交的请求，不代表返回了可锁定的价格。公开实现存在 schema 无法取得时跳过验证的路径，因此还需确认该模型的完整 schema 确实取得，不能把 dry_run 当成无条件严格校验。已有参考文件的任务也不要在“只预览”的要求下偷偷调用上传工具。

用户授权后生成一张

再次确认模型、数量、费用认知与输入未变，随后提交一次。保存实际返回的 prediction ID，后续通过 atlas_get_prediction 查询它。不要假设 MCP 返回的字段与 CLI 一样，也不要因为一次工具调用等待结束就再提交。

媒体结果通常包含远程链接。宿主能够下载时，保存并检查实际文件；不能下载时交付真实链接并说明未保存本地文件。这个 MCP 的上传工具在文档中用于临时素材，不是长期资产托管。

怎样算连接成功

成功启动服务只是第一步。应依次证明：工具可发现，模型 schema 可读取，dry_run 没有提交任务，经授权的生成能查回结果。不要以“配置文件没有报错”代替这四项检查。

本地 stdio 服务不能直接靠粘贴一个 URL 接入网页宿主。需要远程 MCP 时应使用对应的公开接入文档，本篇不猜测服务地址或 OAuth 配置。

04｜面对一大串模型，怎样按输入和用途选择

选择模型先看手里的输入和要交付的东西。一个图片编辑任务即使提示词很短，也不能用只接收文本的模型代替；一个需要透明背景的图标，也不能因为模型画得好看就忽略 alpha 通道。

本次练习为开发者网站制作配图。交付物是一个候选表和一份明确的选择记录；在本篇结束前不产生生成费用。复制 examples/config/model-selection.json 作为决策记录。

先把需求分成硬约束和偏好

硬约束决定是否可用：输入是文本还是参考图，输出文件类型，允许上传的内容，必须保留什么，输出尺寸能否用于页面。偏好只用于可用模型之间选择：画风、速度、费用、可控性。把“最好”“便宜”换成可解释条件，例如“只需要网页背景，先做一张草稿，不要求图片里写中文”。

查询能力，不先提交试试看

atlas models list --type image --json
atlas models search 'image' --json
MODEL='替换为目录中的真实模型ID'
atlas models get "$MODEL" --json

对每个候选记录：是否需要参考图、参数是单图还是数组、输出数量、尺寸选项、可用的报价方法。搜索关键词只帮助发现，不代表搜到的第一个模型就匹配需求。用户点名的模型优先保留，发现能力不符后说明冲突，请用户决定调整要求还是换模型。

做一个有排除理由的候选表

候选 本次输入兼容 硬约束通过 价格信息 决策
从目录复制 A 文本可用 需核对尺寸 估价后填写 可进入预览
从目录复制 B 必须参考图 本次不通过 不再查询 排除
从目录复制 C 文本可用 输出类型待确认 未知 暂停选择

这里的 A/B/C 是教学标签，不能当真实模型 ID 使用。缺失值写“未知”，不要填 0。模型数量多时先按模态和输入能力缩小范围，详细读取两三个候选的 schema 即可。

用最小样本检验选择

选定后按教程 02 预览和估价，获得授权后生成一张。用实际文件检查构图、留白、缩放可读性。第一张满足要求就停止；失败时记录原因，再判断是提示词、参数还是模型能力问题。不要用一次样本宣称某个模型在所有任务上更好。

复制给 Agent

用 Atlas 为这个网站选择一个文本生成图片的模型。先列出输入兼容、画幅、数量和费用认知，不生成内容。最多深入比较三个候选，解释排除理由；模型价格未知时保留未知。选定后等我批准一张样图。

完成的选择记录应能让另一位同事说明“为什么选它、为什么没选另外两个、哪些能力尚未验证”。保留真实模型 ID、schema 核对时间、请求预览与样本评价；只复用选择方法，不把某个模型写成永久默认冠军。

05｜看懂 schema、--explain、dry_run 与费用估算

“这个请求长什么样”“参数是否符合模型”“大概要花多少钱”是三个问题。本篇用同一组文本生图输入，把它们分别查清。最终交付三份记录：schema、请求预览、费用信息；不提交生成。

读取模型参数

mkdir -p tutorial-output/schema-lab
MODEL='替换为已经发现的真实模型ID'
atlas models get "$MODEL" --json > tutorial-output/schema-lab/model.json

查看 required、字段类型、枚举、上下界和默认值。"false" 与 false 不同，图片数组与单一 URL 不同，视频的时长单位也必须确认。不要仅凭字段名字猜测取值。将已确认的模型输入保存为自己的 params.json；本包 examples/config/image.json 的 params 只是教学起点。

用同一输入做预览和估价

PARAMS='./tutorial-output/schema-lab/params.json'
test -s "$PARAMS"
atlas generate image "$MODEL" --params-json "@$PARAMS" --explain --json \
  > tutorial-output/schema-lab/preview.json
atlas generate cost image "$MODEL" --params-json "@$PARAMS" --json \
  > tutorial-output/schema-lab/cost.json

params.json 内只放模型参数，不放 model、凭据或整份 MCP 工具调用。预览后检查 CLI 是否进行了字段映射、采用了哪些默认值。估价和后续执行必须使用同样的模型、尺寸、数量和时长；修改其中任一项后重新估价。

MCP 的对应做法

发现当前生成工具的 schema，确认存在 dry_run，然后用 model、params、dry_run: true 调用。工具返回“预览成功”不代表锁价。本次读取的独立 MCP 实现还允许在取不到模型 schema 时跳过部分验证；遇到这种情况，应停止并补齐 schema，不能把工具返回成功当成必填项全部通过。

本地参考素材的特殊情况

CLI 的预览不上传文件，费用命令也不会为了估价先上传。报价必须要已有 URL 时，先得到用户对上传的授权，再使用该 URL；或者明确指出报价不完整。省略必需参考图得到的文本生图报价，不是原编辑任务的准确报价。

刻意制造一个无费用错误

从真实枚举里选一个不合法值，或把已知数字字段改成对象，只运行预览，观察是否在提交前得到错误。然后恢复原参数。不要为了测试错误使用真实付费提交，也不要把完整 schema 复制进模型输入。完成后保存错误样例，以后升级时复测。

复制给 Agent

检查这份 Atlas 请求。先读取实际模型 schema，对 required、类型、枚举、数量和参考图字段逐项核对。只做 explain 或 dry_run，并单独解释估价；缺少 schema 或价格就报告未知，不上传、不生成、不自动改模型。

验收与排错

能够指出一个参数错误发生在哪一层，并明确“本次未提交”。JSON 语法错误先修语法；模型不接受字段先查 schema；报价服务不可用不代表免费。如果计划改变，把旧预览保留为历史记录，不悄悄覆盖已批准的请求。

06｜升级 Atlas 后，怎样检查旧教程还能不能用

升级后最危险的现象是命令仍能执行，但默认参数或结果结构改变。本篇建立一个无需生成的兼容检查，再把有费用的回归测试留给明确批准的测试账户。

升级前保存一个基线

mkdir -p tutorial-output/compat-before
atlas version --json > tutorial-output/compat-before/version.json
atlas --help > tutorial-output/compat-before/help.txt
atlas skills read atlas --raw > tutorial-output/compat-before/skill.md
atlas generate image --help > tutorial-output/compat-before/image-help.txt

基线还应记录安装渠道、操作系统、宿主与 MCP 包版本，以及当前工作流的配置摘要。不要把 auth 凭据目录打包。项目使用的模型 schema 另存快照，但价格仍需要执行时刷新。

按原渠道升级

npm 安装由 npm 管理，Homebrew 由 Homebrew 管理，原生安装由其支持的更新机制管理。不要同时装几份不同来源的 atlas 再猜正在执行哪份。用 command -v atlas 查看实际入口；PATH 中旧目录排在前面时，升级可能根本没有影响当前进程。

升级后在 compat-after 保存相同四份文件。团队自动化应锁定经过自己验证的版本，不在计费任务执行中自动追浮动最新版。

分四层对照

第一层看命令是否存在；第二层看当前 skills read 的操作说明；第三层用原参数运行 --explain，检查字段、类型和默认值；第四层用已存在的任务 ID 查询结果，观察 JSON 字段。第四层是只读核对，不能为了方便重新生成一批旧任务。

diff -u tutorial-output/compat-before/help.txt tutorial-output/compat-after/help.txt || true
python3 -m unittest discover -s tests -v

diff 的非零返回通常表示存在差异，不等于升级失败。离线测试也只验证本包脚本，不证明当前 Atlas 模型服务可用。遇到 id/prediction_id 差异应修适配器与测试，不让 Agent 从任意 JSON 中猜 ID。

再进行小规模在线回归

由操作者批准一个低风险任务，固定输入与交付规格，记录价格、模型和返回状态。检查参考素材是否真的使用、文件是否保存、下载失败能否仅恢复下载。不要要求生成字节完全相同，除非模型服务明确提供相应确定性保证。

复制给 Agent

帮我核对 Atlas 升级兼容性。保留原账户与环境，只检查版本、命令、内置指南、请求预览和已有任务状态，不创建新的付费任务。把破坏性变化与新增能力分开，给出需要修改的文件和测试项。

通过与回退

能够解释旧流程在哪个版本上通过，哪些字段需要适配。回退客户端不能自动回退服务端模型 schema；一个旧二进制也可能无法继续使用已变更或下线的模型。故障任务仍使用原 ID 查证，勿因回退操作再次计费。

08｜给技术文章制作封面与 Open Graph 配图

为一篇技术文章制作封面与 Open Graph 图片，先把“文章讲了什么”提炼成视觉关系。不要让图像模型发明跑分、论文结论或作者头像。交付包含无字底图和最终带标题版本，方便改标题时复用。

提炼一个画面任务

假设文章主题是“任务中断后如何恢复”，可以画未完成的工作区和被保留的进度；不需要把整篇文字贴到图上。主标题控制为一行或两行，数字与技术名词由作者确认。示例采用 1200×630 作为项目自定输出尺寸；平台预览会改变，发布前用目标平台实际预览核对。

复制给 Agent

先读我提供的文章正文，提炼一个不夸大结论的视觉主题。用 Atlas 做无文字封面底图，给标题留足空间；标题由排版工具添加，技术名词按原文。先展示方案和费用认知，批准后生成一张。再输出我们选定的 1200×630 版本，不上传文章中未授权的客户信息。

制作底图与标题层

按教程 02 生成底图，将构图中的留白与标题摆放联系起来。保存最终接受的原图，再做精确画幅：

python3 scripts/media_ops.py fit-image --inputs assets/article-background.png \
  --output tutorial-output/article/og-background.png --width 1200 --height 630 --mode cover

在你已有的设计工具里放标题、作者署名与项目标识；或使用包内 examples/layouts/title-card.html，替换本地图片及文本，在浏览器里检查固定尺寸后导出元素截图。排版模板不包含字体文件，使用你有权使用的本地字体。没有浏览器导出工具时，可以在设计软件中按同样槽位排版。

检查缩略图而不是只看大图

把最终图缩到信息流中的实际显示大小，确认标题、主体、留白仍清楚。中文易错字、缩写和版本号应逐字核对。给图起有意义的名字，保留 background 和 final 两个版本；不要只保存设计软件截图而丢失原文件。

交付到网页

站点维护者将 og:image 指向部署后可访问的最终图片；file:// 和本地路径不能作为外部抓取地址。图片可访问不代表平台缓存已刷新，更新后检查实际预览。登录才能访问的素材地址不适合作为公开文章的预览图。

验收与常见故障

19｜让一张图片动起来：生成、续查与视频验收

示例目标是 5 秒竖屏镜头。选择模型时必须确认它确实支持相应参考输入、时长和画幅；不支持时应换成经过用户同意的目标或模型，而不是无声丢掉要求。

状态：正文已完成；未执行线上付费生成或宿主实连。依据：S1 / S2 / S3。本地测试范围见 验证报告。

给 Agent 的任务说明

使用 Atlas，把这张参考图做成一个 5 秒竖屏镜头。镜头缓慢推进，主体保持稳定，不改变产品外形和文字。先查图生视频模型与 schema，说明音频支持情况、实际参数和费用认知；不先上传或提交。等我确认后生成一次，保存任务 ID，最后检查真实视频的时长、画幅、运动和声音。超时后继续原任务。

手动路径：先确认模型和素材

set -euo pipefail
REFERENCE='./assets/reference.png'
test -s "$REFERENCE"
atlas models list --type video --json
MODEL='替换为支持本次图生视频要求的真实模型ID'
atlas models get "$MODEL" --json
atlas skills read atlas/references/video.md --raw

找不到与要求相符的模型时应停在这一步。不要拿文本生视频模型假装已经使用了参考图。

在确认 --image、5 秒、9:16 可由当前 CLI 与模型接受后，构建输入：

PROMPT='A single continuous shot based on the reference image. Slow camera push-in. Keep the main subject stable and preserve the product geometry and visible markings. Subtle natural motion, no scene cut.'
INPUT=(-p "$PROMPT" --image "@$REFERENCE" --duration 5 --aspect-ratio 9:16)
atlas generate video "$MODEL" "${INPUT[@]}" --explain --json

分辨率和音频参数应按真实 schema 加入同一 INPUT。不要假设视频一定有声音，也不要把“提示词要求没有声音”当成关闭音频生成参数的替代。费用估算复用同一输入；本地参考与 URL-only 报价的限制见教程 13。

授权后提交一次

下方是付费步骤，只用于首次提交：

mkdir -p tutorial-output
RUN_DIR=$(mktemp -d './tutorial-output/video-XXXXXX')
if ! atlas generate video "$MODEL" "${INPUT[@]}" --no-wait --json > "$RUN_DIR/submit.json"; then
  printf '%s\n' '提交结果需要核对；不要重新运行本生成块。' >&2
  exit 1
fi
PREDICTION_ID=$(python3 scripts/receipt_id.py "$RUN_DIR/submit.json")
printf '%s\n' "$PREDICTION_ID" > "$RUN_DIR/prediction-id.txt"
printf '任务 ID：%s\n' "$PREDICTION_ID"
atlas generate get "$PREDICTION_ID" --json

随后继续这个任务：

atlas generate wait "$PREDICTION_ID" --timeout 10m --json > "$RUN_DIR/result.json"

本地等待结束不等于服务端失败。10m 仅限制这一轮等待；无论超时还是终端中断，都不要靠重复生成来“再等一下”。

技术规格与内容分开检查

从 saved_files 找到实际保存的视频路径。已安装 ffprobe 时可检查容器和媒体流：

VIDEO='替换为 saved_files 中的真实视频路径'
test -s "$VIDEO"
ffprobe -v error \
  -show_entries format=duration:stream=codec_type,codec_name,width,height,avg_frame_rate \
  -of json "$VIDEO"

检查实际时长、宽高关系与是否有音频流。这个命令读取媒体信息，不能证明全片都能正常解码，更不能证明动作自然或口型同步。正式交付还应完整播放，必要时加全片解码检查。

内容检查应回答：是否采用了参考主体，是否出现形变或标识漂移，运动是否符合要求，有没有意外切镜或不需要的声音。对未达标部分如实记录；不能只截一张好看的首帧当作视频通过验收。

交付清单

20｜把三段产品镜头剪成一条完整短广告

本篇把三段各5秒的获批产品镜头剪成15秒短广告。输入来自你已经完成的生成或拍摄；本地剪辑不产生模型费用。最终交付应有一个完整 MP4、字幕与审核记录，不能只给三段链接。

先确认时间线

使用 examples/briefs/product-ad.md 的三镜头练习：全貌、材质、使用场景。每段都应通过产品保真审核。逐段核对时长与画幅；少于5秒的镜头不能悄悄冻结末帧补足而不说明，长度多出的镜头则根据剪辑决定裁切位置。

复制给 Agent

把已批准的三个产品镜头剪成15秒竖屏短广告，不重新生成。先检查每段时长、画幅和产品一致性，再统一视频规格。保留无字幕母版，另外添加我确认的字幕与配音。不要编写新卖点；原音轨是否保留先告诉我。

统一规格再拼接

python3 scripts/media_ops.py concat \
  --inputs assets/shot-01.mp4 assets/shot-02.mp4 assets/shot-03.mp4 \
  --output tutorial-output/ad/picture-master.mp4 --width 1080 --height 1920 --fps 30

此工具会先把各镜头转成相同的画幅、帧率与编码，再拼接；为了后续统一声音，输出故意不含原音轨。不要用它保存有价值的对白；那种项目应在编辑器中逐轨管理。本地转码可能重复/丢弃帧来形成目标帧率，不能把它写成运动质量提升。

添加声音和字幕

python3 scripts/media_ops.py mix-audio \
  --inputs tutorial-output/ad/picture-master.mp4 assets/voice.wav assets/music.wav \
  --output tutorial-output/ad/with-audio.mp4 --music-volume 0.10
python3 scripts/subtitles.py lint --input assets/ad.srt --duration 15
python3 scripts/media_ops.py burn-subtitles --inputs tutorial-output/ad/with-audio.mp4 \
  --subtitles assets/ad.srt --output tutorial-output/ad/final.mp4

mix-audio 按视频时长补静音或裁音频；过长旁白会被截断，因此应先确认稿件时长，不能用该命令解决朗读过长。背景音乐大小是示例值，必须听审。字幕字号与位置也要在实际竖屏预览中确认。

验收整片

python3 scripts/media_audit.py tutorial-output/ad/final.mp4 \
  --decode --width 1080 --height 1920 --duration 15 --require-audio \
  --output tutorial-output/ad/audit.json

技术检查后完整播放，检查切点、产品变化、字幕、声音突变和最后一个字是否完整。报告生成与后处理的各自状态，明确字体与音轨来源。

故障恢复

拼接失败只修视频规格，字幕乱码只修本地渲染环境；缺一个镜头再恢复该镜头任务。不要因为最后的 MP4 没导出就让 Agent 把前三个付费镜头全部重做。交付无字幕母版、最终版和分离音轨，便于后续本地化。

21｜用角色参考制作多镜头视频并检查一致性

多镜头角色一致性需要把身份、服装、道具和场景连续性分开管理。本次制作三段镜头：正面介绍、侧面动作、远景离开。真实人物需有对应授权；练习可以使用你自己设计且有权使用的虚构角色。

准备角色包

使用一张审核过的主参考，必要时补侧面与全身参考，检查这些图本身是否属于同一角色。写清不可改变的特征，例如发型、外套、配饰、主色；把表情、动作和镜头大小列为可变项。角色包不是人物识别数据库，不附真实人物私人资料。

复制给 Agent

用 Atlas 为我提供的角色参考制作三个连续镜头。先确认参考图彼此一致，按 schema 选择支持角色/图像参考的模型。固定发型、衣着、道具与场景方向，只改变镜头和动作。先生成一段验证参考有效；批准后再做另外两段。保留失败样例，不靠换脸或虚构授权补救。

镜头级计划

镜头 变化 固定项 特别检查
01 正面 轻微表情 发型、上衣、配饰 五官与参考关系
02 侧面 转身拿道具 道具形态、手的左右 遮挡后是否换人
03 远景 离开画面 服装、运动方向 全身比例与步态

把每镜头作为独立任务保存，附相同参考与其特定动作。模型支持多参考时按照实际数组字段填写；不支持时不要把数张图拼成复杂图再假装获得原生多参考能力。使用上一镜头末帧可能帮助衔接，也可能把错误累积到下一镜头，应同时核对主参考。

逐段与跨段检查

完整播放每段，检查转头、遮挡、远近变化是否造成身份漂移。把第一帧、中间帧和最后一帧并排仅作辅助，全片仍要看。跨镜头检查道具换手、衣服颜色、光照方向和动作结束状态。不要让自动人脸相似度成为唯一判定，它无法评价剧情连续性，也不能证明身份授权。

修复策略

只有局部镜头失败时，缩小该镜头的动作幅度或改变拍摄距离；在用户批准的范围内重新生成该镜头。主参考本身矛盾则先修角色包。模型不支持必需控制时报告能力缺口，不能偷偷更换用户指定模型或扩展预算。

完成标准

交付三段审核过的镜头、角色包版本、镜头连续性记录及未通过事项。成片可以按教程20合并。保留“生成一致性通过”和“角色权利已确认”两个独立结论，技术相似不等于有权使用。

22｜原生音频与后期配音，怎样选择和对齐

视频声音可以随模型一起生成，也可以后期加入旁白、环境音与音乐。本篇用一条无口型要求的产品镜头练习两条路线的取舍。目标是得到与画面长度一致、内容准确的声音方案。

先核对模型能力

在当前 video schema 里找音频相关能力与字段，不默认所有模型都有音轨。字段可能是布尔开关，也可能根本不存在。提示词写“静音”不能替代实际参数；工具返回 MP4 也不能证明里面有音频。

原生音频适合探索氛围或模型能满足的同步效果；必须逐字准确的产品讲稿、后续要多语言复用的旁白，通常更适合独立录音或 TTS 再合成。这里是本任务的工程取舍，不是所有模型的质量排名。

复制给 Agent

先检查我选定的视频模型能否生成音频。给出原生声音和后期配音两条方案，说明能否保证使用我的准确讲稿。不要在没有批准时生成两份视频。最终检查实际音轨、讲稿完整性和时间对齐；视频自带声音不代表内容已审核。

检查已有视频音轨

python3 scripts/media_audit.py assets/clip.mp4 --output tutorial-output/audio-choice/probe.json

如果没有音频，明确报告，而不是让播放器静音设置成为唯一诊断。已有音频应先听审：是否有随机对白、错误发音或不合适的音乐。是否保留由使用者决定。

后期配音路径

按教程25准备旁白，先测量实际时长。需要15秒视频时，旁白宜在结尾留出自然停顿，具体时长由剪辑决定。示例合成会替换视频原音轨：

python3 scripts/media_ops.py mix-audio --inputs assets/clip.mp4 assets/voice.wav \
  --output tutorial-output/audio-choice/vo-version.mp4

该脚本不会拉伸语音，会按视频时长补静音或截断。因此旁白过长时应改稿或明确调整视频，不直接截掉结尾后交付。需要保留原始环境声时使用多轨编辑器或另写经测试的混音步骤，不能假设这个简化脚本保留了原声音。

验收与恢复

完整听一遍，检查关键数字、品牌名、开头与结尾。声音与画面有因果动作时按帧核对；无口型要求也要避免声音出现时物体尚未动作。音轨错只重新配音/混音，视频画面不必重新生成。交付无声母版、原音轨版本、旁白与最终混音，标明最终选择。

23｜用首尾帧控制镜头，识别模型的能力边界

首尾帧控制的目标是让一个镜头从给定画面开始，在给定画面附近结束。中间运动是否自然仍需要检查。本篇制作一个产品从正面转到轻微侧面的短镜头，不把两个完全不同的物体强行当成连续状态。

先确认存在这项能力

查询当前模型 schema，确认有两个不同的图像输入或其他正式支持的首尾帧机制。CLI 存在 --end-image 这个选项不代表所有模型都接受它。没有对应能力就停在选型，或经用户同意改为两段镜头剪辑；不能把第二张图塞进 prompt 假装执行了控制。

准备两张相容的图

保持产品、光照和画幅一致，末帧只改变合理的角度或位置。先按教程16调整两图尺寸，检查输入图本身有没有标签变化。两张参考相矛盾时，模型可能扭曲中间帧；先修输入比长提示词更可控。

复制给 Agent

使用这两张获批准的图片作为开始与结束状态。先查 Atlas 当前模型是否真的支持首尾帧；支持后展示两个输入字段及费用认知，不上传或生成。批准后提交一次，完整检查起点、终点和中间运动；没有该能力就明确停止，不退化成普通文生视频。

CLI 预览示例

只有当前模型与 CLI 的映射都已确认时才执行：

MODEL='替换为支持首尾帧的真实模型ID'
atlas models get "$MODEL" --json
atlas generate video "$MODEL" \
  -p 'A continuous gentle orbit from the first reference to the final reference. Preserve product geometry and markings.' \
  --image @assets/start.png --end-image @assets/end.png --explain --json

在预览里确认两个文件都映射到实际输入，不要忽略未知字段警告。根据 schema 补时长和画幅，再按教程19的授权、提交、续查流程执行。上传和价格限制与其他参考图任务相同。

验收：不能只看两头

保存实际视频，分别比较首帧、末帧与输入，再慢放中间运动。检查是否出现交叉溶解式变形、物体翻转、文字漂移或突然切换。第一帧压缩/色彩差异不必要求字节完全相同，但内容偏差应有明确容忍标准。

失败与交付

中间动作复杂时先缩小角度、延长允许时长或改变镜头设计，任何新的生成都计入授权。结果只能完成起点却无法符合终点时，报告部分完成，不说“首尾帧锁定成功”。交付参考对照、真实视频、模型与任务记录。

24｜延长已有视频：接缝、动作和声音怎样检查

延长已有视频要检查三件事：模型是否真的使用原视频、接缝是否连续、声音是否衔接。本篇先完成视频延长的能力检查，再把生成片段与已有素材组合；没有该模型能力时提供一个本地剪辑替代，但明确它不等于生成式延长。

能力分支

在目录搜索 video extend，读取实际模型说明，确认输入是整段视频、末帧、还是一个已有生成任务引用。普通 image-to-video 从末帧生成后续片段，只能称“末帧续接”，不能冒充原生视频延长。不要创建未经证实的 atlas extend 命令。

复制给 Agent

我要延长这段获授权的视频。先确认 Atlas 当前账号有没有相应模型，核对输入类型、时长上限、声音处理和输出是完整视频还是新增片段。批准后只提交一次。若没有能力，不生成替代任务；给出末帧续接或本地剪辑的区别，让我选择。

准备原片

保存原始文件，不在其上覆盖。检查实际帧率、时长、色彩与音轨。最后一秒应有稳定且可延续的动作；快速切镜、黑场、片尾字幕通常不适合直接延长。必要时先剪到一个合理接点，但保留剪切记录。

python3 scripts/media_audit.py assets/original.mp4 --decode \
  --output tutorial-output/extend/original-audit.json

参数与提交

支持视频输入的模型，按 schema 使用 --video 或对应字段，在 explain 中核对原文件确实进入请求。只接末帧的模型则按教程19执行，并在记录中标注路线。实际时长与分辨率依模型能力选择，不能假定请求5秒就一定精确返回5秒。

收到结果先检查其内容是“原片加新增部分”还是“仅新增部分”。把完整结果再拼到原片后，会重复播放原内容；必须先核对这一点。

接缝检查

在接点前后各看一小段，比较主体位置、速度、运动方向、曝光与镜头轨迹。声音另听爆音、突变与重复对白。跨淡化只能遮盖轻微差异，不能修复身份改变或动作逻辑错误。字幕时间轴需要按最终剪辑重新检查。

本地替代与恢复

用户接受停格或重复镜头时，可在编辑器里复制片段/保持末帧，并清楚标为剪辑扩展；不能声称模型预测了后续动作。生成超时沿用原 ID；接缝失败只重做新增部分。交付原片、新增片段、最终版与接点审核记录。

25｜把脚本生成配音，检查数字、专有名词与停顿

本篇交付一段可听的配音、最终口播稿，以及数字和专有名词检查记录。先把内容审定，再合成声音；否则每次改一个产品名称，都可能需要重新付费。示例文本使用虚构品牌，不克隆任何人的声音。

准备文稿与声音要求

将口播稿保存为 UTF-8 文本，写清语言、情绪、目标时长和使用场景。把“3.5”“2026”“API”“DeskLight”等读法另记在 发音表。界面显示文案与实际发音文本可以不同，但不要擅自改动事实、金额、单位或人名。

目标时长是验收条件，不是所有 TTS 模型都有的参数。先用实际稿件读一遍，再决定删字、拆段或调整停顿；不要为了塞进十秒把声音加速到无法听懂。

复制给 Agent

用 Atlas 为我的已审定文稿制作普通合成配音，使用当前可用且适合中文的标准声音，不克隆真人。先查询 TTS 模型、语言、voice 和输入字段，预览完整请求与费用认知。等我确认后生成一次，保留任务 ID。交付音频、实际时长、数字和专有名词的逐项听检结果；未听检的部分明确标注。

选择 TTS，而非音乐或转写模型

CLI 支持音频命令的安装版本可以先执行：

atlas version --json
atlas models list --type audio --json
MODEL='替换为目录中的TTS模型ID'
atlas models get "$MODEL" --json
atlas skills read atlas/references/audio-3d.md --raw

同属 audio 不代表用途相同。核实模型用途是文本转语音，查看文本字段究竟叫 text 还是其他名称，voice 是枚举、ID 还是可选默认值。不把音乐模型当作配音模型。如果当前 CLI 没有该命令，转到已连接 MCP 的 atlas_list_models、atlas_get_model_info 与 atlas_generate_audio 路线，不猜命令别名。

复制 图片配置 为你自己的 voice.json，将 kind 改成 audio，填入真实模型与已核对的参数，删除不适用的 prompt。该配置是本包脚本输入，不是服务端原生请求体：

python3 scripts/run_job.py prepare --config voice.json --run-dir tutorial-output/voice-01
python3 scripts/run_job.py preview --run-dir tutorial-output/voice-01

只有确认本次费用与上传范围后，执行付费步骤：

python3 scripts/run_job.py submit --run-dir tutorial-output/voice-01 --approve
python3 scripts/run_job.py wait --run-dir tutorial-output/voice-01

对照文稿逐句听

先用 media_audit.py 读取时长和音轨，再完整播放。数字、单位、缩写、品牌、人名各听一遍；注意句末是否被截断、词间是否出现不自然停顿、情绪是否偏离使用场景。机器转写回听可以辅助发现漏词，但不是正确发音的证明，额外转写同样可能计费。

python3 scripts/media_audit.py ./assets/voice.wav --require-audio --decode

路径需要替换成实际文件。若只发现一句读音错误，先修改对应短段并获得必要授权，重新生成该段后再合成。不要让 Agent 为比较几十个声音自动连续下单。提交过且正在处理的音频仍应续查原 ID。

26｜从录音得到转写和字幕，检查时间轴

从录音得到“可读文本”和得到“能同步播放的字幕”，是两项交付。字幕还需要可靠时间戳、分句和人工复核。本教程先检查 ASR 返回能力，再把实际结果转换为 SRT，不通过平均分配时长伪造对齐。

27｜给同一条视频制作多语言版本

28｜用获授权肖像与声音制作讲解视频

在生成前检查授权范围

记录肖像来源、被表现者同意的用途、声音来源、发布渠道、授权期限和是否允许修改文稿。授权文件可以存于受控系统，本地清单只保存引用编号，不必把签字或证件交给模型。标准 TTS 与声音克隆应区分；本教程默认使用标准声音，不教授仿冒未经同意的真人。

用我明确授权的肖像与文稿做讲解视频，使用标准合成声音。先检查当前 talking-avatar/lipsync 模型的输入与时长限制，解释会上传什么、如何标识合成内容及费用认知。没有所需授权或能力时停止。确认后只执行获批的文稿，不让人物说额外的话，交付完整视频和口型、声音、披露检查结果。

取得上传许可后，把肖像和声音变为当前模型支持的输入。保留素材校验值、具体模型 ID 和两次任务 ID。不要将真实本地文件名放进 prompt 后当作已经上传。

30｜处理长录音：分段、合并与专有名词校正

长录音要先分段，再转写和合并。难点在于模型输入限制、分段边界与时间轴；把每段的文字直接拼接，很容易重复一句话或丢掉片段交界处的词。本包脚本只做本地切分与时间偏移，不替你调用 ASR。

了解原始文件

先保留母版，记录采样率、声道、时长和授权范围。若说话人分别位于不同声道，直接合成单声道会失去分离线索；本篇的分段脚本为了教学统一输出单声道 16kHz PCM，使用前应确认这符合本次识别要求，否则在可信音频工具中保留声道后单独处理。

处理这段获授权的长录音，先查模型的语言、时长和体积限制，再提出分段计划，暂不上传。每段保留在原文件里的起止时间、请求 ID 和转写状态；不要自动重提未知受理的片段。合并时核对重叠语句，不能把每段时间戳都当成从整段录音起算。

本地切分并保存偏移

下面的 120 秒片长、2 秒重叠是教学选择，要根据实际模型限制调整。PCM 体积也必须检查，不能只看时长。

python3 scripts/audio_chunks.py --input ./assets/meeting.wav \
  --out tutorial-output/meeting-chunks --seconds 120 --overlap 2

输出 chunk-0000.wav 等文件与 chunks.json。manifest 中的 offset_seconds 是这段在原录音中的位置；segments_file 表示后续应保存的 ASR 中间结果，此时文件还不存在，transcribed 为 false。脚本没有发网络请求。

每段音频分别使用已验证的 ASR 请求并独立保存回执。先跑一段确认能力、识别效果和费用，再批准余下片段；不要把整个目录一把上传而不设数量和并发边界。重试只针对已确认可重新执行的片段。

保存片段内时间戳

把每段实际返回结果转换为 26 的 start/end/text 数组。先确认这些时间相对于片段起点；若上游返回全局时间，不能再加一次 offset。将中间文件保存为清单中指定的名字，再编辑供合并使用的清单，去除失败或未识别项，不能填空数组冒充已经转写。

python3 scripts/subtitles.py merge \
  --input tutorial-output/meeting-chunks/chunks.json \
  --output tutorial-output/meeting-merged.srt

脚本会加偏移、排序并检查结构。默认拒绝重叠字幕；存在切片重叠时，先人工听取边界，决定保留哪段文本与时间范围，再合并。不要仅按相同字符串去重：讲话者可能真的连续重复同一句话。

35｜交付前检查容器、分辨率、帧率、时长和音轨

本篇建立交付前的技术检查。它回答文件是否存在、媒体流是什么、是否满足指定规格、能否完整解码；不会回答创意是否优秀、字幕是否准确或产品是否变形。把两类检查分开，才能避免“FFmpeg 没报错”被当成最终作品合格。

写明期望规格

从需求中取出容器、分辨率、时长、是否必须有声音，以及可接受的误差。不要看到文件是 MP4 就假定它是 H.264，也不要仅看编码头把可变帧率认定为恒定帧率。旋转标记、像素长宽比、色彩空间与 HDR 信息都可能影响实际显示。

检查交付目录里的视频，只做本地读取与解码，不上传、不重生成。先核对实际宽高、时长、音轨和容器，再检查整片能否解码；对帧率、旋转和色彩的未知情况明确说明。把技术检查和人工视觉/声音检查分开记录。

基础命令与严格检查

python3 scripts/media_audit.py ./assets/final.mp4
python3 scripts/media_audit.py ./assets/final.mp4 \
  --width 1080 --height 1920 --duration 15 --tolerance 0.2 \
  --require-audio --decode --output tutorial-output/final-audit.json

这里的 15 秒±0.2 秒是示例验收，不是所有平台规范。脚本返回 0 表示本次指定的检查通过，1 表示发现规格或解码问题，2 表示无法完成检查。没有传某个规格就不会检查该项；content_review 始终为 not_performed。

默认全片解码上限为 180 秒，需要更长检查时显式使用 --decode-timeout。达到本地上限应报告未完成解码，不能将其解释为视频坏了或解码已通过。只读元数据时没有遍历每一帧。

看报告里容易被忽略的字段

检查 video 和 audio 数组，而不是只看第一个数值。avg_fps 和 r_fps 不一致时记录原因待查；二者相同也不能单独证明 CFR。sample_aspect_ratio 非 1:1 或包含 rotation 时，编码宽高与显示宽高可能不同。缺失 duration 不可自动当作零秒内容。

如果需要固定编码、音频采样率或码率，先读报告，再在可信转换流程中明确设置并复检；本包脚本不会替你悄悄修复所有问题。两次转换造成的损失也应纳入结果说明。

将验收产物与运行日志分开

把最终文件与必要的人工审核记录放进专用交付目录，先确认没有 API key、客户未授权资料或内部 URL，再建立文件清单：

python3 scripts/manifest.py --root ./delivery --output ./delivery/manifest.json

manifest.py 记录字节数和 SHA-256，拒绝符号链接；它不做敏感信息识别，也不能证明版权或内容准确。发送前后比对摘要，可以检查传输是否改变了文件。

下载中断先重取原任务结果，码流损坏检查源文件或重新下载；规格不符再考虑本地转码；运动形变属于内容问题，可能涉及重新生成。每一类应保存不同原因，避免一个笼统失败码让自动化系统把整条链重跑并重复付费。

36｜图片生成 3D 资产后，怎样检查与导出

生成出 GLB 或 OBJ，只证明取得了某种文件，不等于资产能直接进入游戏、网页或制造流程。本篇以通用 glTF/GLB 交付为例，检查结构、纹理、尺度与外观；不承诺生成资产拥有可制造的拓扑或可动画绑定。

先定义目标用途

网页展示通常关注加载体积、纹理和渲染效果；游戏还需要面数、材质数量、碰撞体和性能约束；3D 打印则要另查封闭性、厚度与真实尺寸。记录目标工具和格式，避免拿一张预览图当成网格交付。

用 Atlas 从我的获授权参考图生成一个用于网页展示的 3D 资产。先确认模型的 3D 能力、输入与输出格式，说明不可见背面可能被猜测，确认后生成一次。交付真实网格、纹理与预览，并检查加载、尺度和材质；不声称已经通过制造或游戏性能验证。

生成与产物选择

独立 MCP 中 3D 归入 Image 类型，并通过 atlas_generate_image 路线处理；CLI 则仅在当前版本和账户目录支持时使用 3d 路径。先读模型详情，确认是 image-to-3D 还是 text-to-3D，不能把普通图片输出当成模型文件。

atlas models list --type 3d --json
MODEL='替换为当前账户可用的3D模型ID'
atlas models get "$MODEL" --json

上传参考与生成需要明确授权。回执中可能同时有 GLB、ZIP 和渲染预览；逐一记录真实类型，不只下载第一项。ZIP 解包前审查目录，拒绝绝对路径、上级目录穿越、符号链接和异常大文件；不要执行包内脚本。

结构校验与本地导入

Khronos glTF Validator 可检查 glTF/GLB 的规范问题。使用官方工具，按其说明验证并保存报告；不把商业保密模型上传到未经批准的服务。规范错误与警告分开检查，验证器通过并不代表几何正确、材质好看或运行性能达标。

在已安装的可信 3D 编辑器中导入实际资产。Blender 等工具的导入位置与版本有关，按当前安装界面选择 glTF/GLB 导入，不复制未知来源的自动执行脚本。旋转观察正面、侧面和背面，检查缺面、法线、透明材质、贴图丢失、比例与中心位置。

处理与重新导出

先保存原始生成文件，再在副本上处理多余网格、材质和尺度。单张图看不到的背面可能是生成的假设，重要物体应补充真实参考或人工重建。调整面数、压缩纹理、改变单位后，重新导入导出文件，避免导出选项漏掉贴图或对象。

网页验收需在目标渲染器加载，检查旋转、缩放、移动端内存和透明效果。不要用桌面编辑器预览正常来证明所有终端可用。模型转换为另一个格式也不能通过改后缀完成。

最终交付

交付原始资产、处理后的发布资产、纹理（若外置）、预览、校验报告和单位/面数/修改记录。使用本包 manifest 对专用交付目录建立摘要；保留未通过项，例如“背面细节未核实”“未绑定骨骼”“未测试 3D 打印”。结构或导出失败先在本地修复，不默认再调用生成模型。

37｜用 Python 调用 CLI，持久保存每次任务回执

本篇用 Python 调用 Atlas CLI，并把一项业务操作对应到一个稳定目录。目的在于保留请求、受理状态和产物位置，尤其避免脚本在等待超时后从头重新生成。随包的 run_job.py 是教学包装器，不是 Atlas 官方持久工作流服务。

配置与目录

准备 Python 3.10+ 和已登录的 Atlas CLI。先从当前目录选模型，检查必填参数与价格，再把实际参数写入配置。样例 image.json 的模型 ID 是故意设置的不可用占位，不改就会被拒绝。

atlas version --json
atlas auth status --json
atlas models list --type image --json

本包配置只有 kind、model、params。params 是已经核对的模型参数，不能包含凭据或覆盖 model。包装器不映射本地 @file 媒体，只接受获授权的 URL；需要上传本地参考时先按 13 处理，不把本地路径当成远程 URL。

将这个已核对请求作为一项稳定操作执行，使用固定 run 目录。先准备与预览，不提交；授权后只提交一次，保存任何返回的 ID，即使进程退出非零。等待失败只查原任务，受理未知时停止重提，不删除 attempt 标记来绕过保护。

分开运行，分开观察

python3 scripts/run_job.py prepare --config my-image.json --run-dir tutorial-output/job-001
python3 scripts/run_job.py preview --run-dir tutorial-output/job-001

prepare 只写本地文件，preview 调用 CLI 的 --explain，可能读取当前目录但不提交生成。价格需要另用正式估价入口，不能把 preview 当成报价。审查 plan.json 和预览后才进入付费步骤：

python3 scripts/run_job.py submit --run-dir tutorial-output/job-001 --approve
python3 scripts/run_job.py get --run-dir tutorial-output/job-001
python3 scripts/run_job.py wait --run-dir tutorial-output/job-001 --wait-seconds 600
python3 scripts/run_job.py inspect --run-dir tutorial-output/job-001

这些是独立阶段，不要在有 set -e 的一条 Shell 链里盲目串联。包装器退出 3 代表已知处理中，4 代表已知远程失败，2 代表错误或未知，0 才是本次阶段满足成功条件。被接受的异步提交通常就是处理中，所以 3 不代表需要再提交。

标记能保护什么，不能保护什么

提交前，脚本通过独占创建 attempt.json 记录一次尝试；同目录第二次提交会被阻止，崩溃也不自动移除。请求与参数有摘要校验，修改原计划会被拒绝。命令通过参数数组执行，不用 Shell 拼接，因此 prompt 不会直接成为 Shell 命令。

这些措施只约束这个目录和包装器。新建另一个目录、另一台机器或直接调用 API 仍可能产生新任务；客户端文件不能保证服务端 exactly-once、跨设备额度或账号级幂等。共享不可信目录也不是安全边界。

测试与接入应用

先运行离线测试：

python3 -m unittest discover -s tests -v

测试用模拟调用覆盖超时、非零退出仍有 ID、未知状态、计划变化与重复提交，不实际调用 Atlas。将其接入应用时，可导入模块或使用 subprocess 参数数组启动；不要让外部请求指定任意 --atlas 可执行路径。

日志包含 prompt、素材 URL 和路径等业务信息，应保存在受控位置；不要把完整 run 目录当成默认公开 artifact。成片验收另用 35，不要把 wrapper 成功当成画面质量通过。

38｜把媒体生成功能接进 Node.js 项目

本篇提供一个不用第三方 SDK 的 Node.js REST 示例。它覆盖本地准备、单次提交和原任务查询，适合学习后端集成；它不是面向所有业务的生产 SDK，也不内置实时模型发现、报价、认证刷新或文件上传。

保持三种接口形状清楚

CLI 使用命令参数，MCP 生成工具常接收 {model, params, dry_run}，公开媒体 REST 的请求体则按所选模型使用展平字段。随包配置仍是 {kind, model, params}，客户端会编译为 {...params, model}，不把配置原封不动当 API 请求。

接口路径依据公开 MCP 源码核对：图像 /api/v1/model/generateImage、视频 generateVideo、音频 generateAudio；3D 使用图像路径并要求先核实模型能力；查询为 /api/v1/model/prediction/{id}。模型是否当前可用、必填项和价格仍需单独查询。

帮我用 Node 接入 Atlas 的媒体生成接口，先完成本地配置和假响应测试，不调用付费接口。密钥只保留在服务端，POST 不自动重试。上线后保存每次尝试、原始回执与任务 ID，浏览器只拿业务任务 ID；不要把服务端 API key 发给前端。

从可运行示例开始

文件在 atlas-media.mjs。推荐使用仍在维护的 Node 22 或更高兼容版本；脚本利用内置 fetch。准备经过 schema 核对的 my-image.json，先执行不联网的两个动作：

node examples/node/atlas-media.mjs prepare --config my-image.json --run-dir tutorial-output/node-001
node examples/node/atlas-media.mjs preview --run-dir tutorial-output/node-001
node --test tests/node-client.test.mjs

**这里的 preview 仅展示 REST 请求体，不等于 CLI 的在线 schema 编译，更不是 MCP dry_run 或报价。**测试使用注入的假 fetch，不读真实 API key、不发送网络请求。

授权后才让进程安全获取 ATLASCLOUD_API_KEY；不要写进代码、网页或 Git。下面是实际付费入口：

node examples/node/atlas-media.mjs submit --run-dir tutorial-output/node-001 --approve
node examples/node/atlas-media.mjs get --run-dir tutorial-output/node-001
node examples/node/atlas-media.mjs wait --run-dir tutorial-output/node-001 --seconds 120

与 Python 包装器相同，退出 3 表示仍在处理，2 表示错误/未知，4 表示远程失败。请求可能已经受理但响应丢失，不能据此自动再次 POST。attempt.json 永不自动清除。

认证、查询与下载的边界

示例固定请求源站并拒绝 HTTP 重定向，不会把 Authorization 附到输出 CDN URL。查询返回中的非 2xx 也可能描述终态失败，要读 task status；401/403 停止，不擅自换账号。GET 可继续查询，但不能沿用 GET 重试策略去重试付费 POST。

脚本不下载媒体。应用需要下载时，先核实结果来自对应任务，再使用不带 Atlas key 的受控下载器；限制来源、协议、重定向、大小和本地路径，不能向用户任意指定的内网 URL 发带凭据请求。

接入你自己的服务

浏览器调用你自己的业务接口，服务端将业务 ID 映射到 Atlas ID，数据库持久化账户、请求摘要和状态。只有所属用户能读该任务。使用队列处理长任务，并区分任务完成与产物保存。本文的本地目录教学方式不能替代多租户数据库、账务限制、审计和并发控制。

最小验收包括：请求体没有多余 params 包装、密钥未输出、一个操作只发一次 POST、非零 HTTP 返回中的任务 ID 不丢失、查询错误不更换账户。假响应测试通过后，再按明确授权做一项真实小任务联调，核对正式 API 的返回形状。

受理未知的请求进入核对队列，原任务成功只重试下载；这些流程在 42 与 45 继续展开。

39｜在 GitHub Actions 中生成发布素材

在 CI 中生成发布素材，需要显式触发、固定代码来源、保护凭据和保存回执。不要把付费生成默认挂在每个 PR 或每次 push 上。本包提供手动触发示例，并将“只预览”和“真的生成”分开。

示例的具体保护

manual-generation.yml 放在 examples 目录，不会自动启用。它采用 workflow_dispatch，只允许私有仓库的 main 分支，execute 默认 false，固定单次图片提交。生成 job 使用名为 atlas-generation 的 environment，必须由你在仓库中配置审批人和密钥；写了环境名并不会自动创建审批规则。

为这个私有仓库配置一条手动生成发布素材的 CI，默认只做请求预览。只使用受信任分支代码，API key 存于受审批环境。提交后保留回执，不因 workflow 重跑而重新生成；失败后先核对原任务。不要配置 pull_request_target 来运行贡献者代码并读取生成密钥。

准备仓库与参数

先把所需教程脚本审阅后放入目标仓库，核对真实模型 schema、价格和示例 prompt。复制 YAML 到 .github/workflows/ 后再检查 paths。当前示例使用 Node REST 客户端，因此托管 runner 不需要额外安装 Atlas 二进制；已有安全安装渠道的自托管 runner 也可以用 37 的 CLI 包装器。

40｜把 n8n 接成内容生产流程

n8n 可以把素材输入、Atlas 生成和后续分发连起来。本教程先做一条手动触发的最小流程，区分提交节点与状态节点，再增加业务持久化。已有社区节点时优先检查实际版本，不按照旧截图猜参数。

安装与最小导入

在你获授权管理的 n8n 环境安装 n8n-nodes-atlascloud 社区包，确认实例允许该包以及当前节点版本。使用 Atlas Cloud API credential 保存密钥，不写在 Code 节点、HTTP body 或可公开导出的 JSON 中。

导入 n8n-submit-poll.json。它按照实际公开节点结构编写，包含 Manual Trigger、Atlas Task Submit、Atlas Task Status；没有有效凭据，模型是不可用占位，必须从当前节点下拉框重新选择并补上必填字段。未激活工作流不代表点击 Test 不收费。

帮我接通 n8n 的 Atlas 内容流程，先只检查节点、凭据引用和参数，不执行生成。确认后一次提交，保存实际 prediction ID，再由 Status 节点查询；下载或发布失败不重新执行 Submit。任何对外发布先经过人工验收。

配置提交与查询

Task Submit 选择当前实际 Category、Model 和 Submit Only。Task Status 的公开示例从 {{$json.prediction_id}} 读取 ID；你仍要观察当前节点真实输出，因为不同包版本可能改变形状。最小示例中的等待时间字段单位由该节点界面定义，不能根据数字 15 猜是十五秒还是十五分钟。

先在明确批准的单项素材上运行，确认 ID 已持久保存、Status 返回实际状态。状态未完成时只继续查询。设置节点重试时不要把所有错误统一设为“重跑提交”，尤其是请求超时或响应丢失。

生产使用要补外部状态表

最小 JSON 为教学图，没有数据库账本。要做批量业务，先用可靠存储保存业务 item ID、账户、请求摘要、attempt 状态和 prediction ID，再分支到轮询与下载。执行记录保留时间可能有限，不能把 n8n 的一次运行日志当作永久账本。

提交节点发请求前写 attempt，受理后更新 ID；GET/状态节点出错可以恢复原查询。对未知受理项保留人工核对队列，不能通过清空状态重新触发。

下载、字幕与发布

只有已确认成功并拿到目标产物时，才调用 HTTP Request 下载文件。下载 URL 不应携带 Atlas 的 Authorization；按允许的来源和体积限制下载，不让用户任意提供的 URL 访问内网。进入下一步时检查 binary 数据是否确实存在，而不是只传递一个过期链接。

有需要时把成片交给专门的受控后处理服务，再执行 35 的检查与人工批准。自动发社媒、邮件或 CMS 是额外动作，应有明确发布授权，不能由“帮我生成素材”推断。

n8n Wait 节点能够按时间或自身 webhook 恢复，但这不证明 Atlas 生成接口支持回调参数。没有明确平台契约时走状态查询；如需 webhook 通知，由你的服务在核实 Atlas 任务后发给自己的 n8n 流程，详见 42。

42｜轮询与 webhook：怎样可靠等待生成结果

媒体生成通常比一次工具调用持续更久。可靠的等待方式要保存任务 ID，让等待进程可恢复，并把本地超时与服务端终态分开。本篇先提供能执行的轮询，再说明 webhook 在系统里的正确边界。

最小可执行等待

已有 Node 示例 run 目录与 ID 时，直接查询，不重新提交：

node examples/node/atlas-media.mjs get --run-dir tutorial-output/node-001
node examples/node/atlas-media.mjs wait --run-dir tutorial-output/node-001 --seconds 120

或者使用 CLI 的原 ID：

PREDICTION_ID='替换为真实已受理任务ID'
atlas generate get "$PREDICTION_ID" --json
atlas generate wait "$PREDICTION_ID" --timeout 10m --json

等待上限只限制本地进程。结束时仍在 processing，就记录“仍处理中”；不要转成生成失败，也不要新发一个请求当作延长等待。任务只有实际返回终态时才更新终态。

对已受理的 Atlas 任务实现可恢复等待。只查询原 ID，保留账户与任务关系，按有限间隔轮询并设置本地截止时间；401/403 或 ID 不一致时停止，不更换账号。超时记录 pending/unknown，不再次提交。

应用里的持久状态

至少保存业务任务 ID、Atlas ID、账户引用、请求摘要、上次检查时间、下一次检查时间和终态。工作进程从队列领取待查询项；同一任务的状态更新使用乐观锁或数据库事务，防止多个 worker 互相覆盖。

对 429、可恢复网络错误和非终态 5xx 使用有上限的退避与适当抖动；收到服务端重试提示时按契约处理。HTTP 5xx 内部可能已经返回 failed 的任务体，不应无限重查该终态。具体限流配额需要实际接口说明，本篇不给一个虚构的“安全 QPS”。

未核实 Atlas 回调参数，先不要编造

本次查阅的契约不足以确认可通用使用的 Atlas webhook 注册字段、签名算法与事件投递保证。因此本包没有 callback_url 或 webhook_secret 的假执行示例，也不把 n8n 的 Wait URL 写成 Atlas 原生回调功能。

如果需要对你的应用发通知，可以由你自己的查询服务在确认终态后，将一个内部事件写入数据库/outbox，再投递到你控制的队列或回调接口。事件包含业务任务 ID、已核实状态、事件 ID 和版本，不含 API key。接收方验证你定义的身份与签名，并按事件 ID 去重。这是你的应用协议，不是 Atlas 标准。

真有官方 webhook 后仍需核对

上线前必须确认注册入口、签名覆盖字节、时间窗、重投机制、重复与乱序语义。验证事件后仍核对账户/任务归属，必要时读回服务端任务。不要允许某个伪造回调直接把另一个用户任务标成完成，或触发对任意 URL 的带凭据请求。

通知投递采用至少一次时，接收方应幂等处理；“事件发出”“用户收到通知”“生成已完成”“文件保存完毕”仍是不同状态。通知失败重发通知，不重生成媒体。

交付本教程时保留一次从 pending 到终态的实际状态记录，以及超时/重复查询测试。随包测试为模拟接口，不声称已经验证 Atlas 云端 webhook。

43｜等待超时或下载失败后，继续原任务

你已经点过生成，现在终端超时、Agent 会话断开，或者 API 显示成功但找不到文件。先不要再次运行生成命令。要判断的是原请求现在处于哪个阶段。

状态：正文已完成；未执行线上付费生成或宿主实连。依据：S1 / S2 / S3。本地测试范围见 验证报告。

第一种：已经有任务 ID

把它当作原任务的唯一查询入口：

PREDICTION_ID='替换为已返回的真实任务ID'
atlas generate get "$PREDICTION_ID" --json

如果还在处理，继续查询或等待原任务：

atlas generate wait "$PREDICTION_ID" --timeout 10m --json

不要仅根据 Shell 退出码判断结果。终态为 failed 或服务端 timeout，与本地 wait 达到时间上限，是不同情况。终态失败也不自动授权换模型重试。

给 Agent 的恢复指令可以这样写：

这个 Atlas 任务的 ID 是【填入真实 ID】。只查询和继续等待该任务，不要重新生成、切换模型或账户。远程完成后尝试取回已有产物；如果保存本地失败，告诉我远程链接、具体阶段和未完成事项。

第二种：生成已完成，但文件没保存下来

比较远程 outputs 与本地 saved_files，再检查实际路径是否存在、文件是否非空。一次远程成功不证明下载成功。

继续原任务的读取/下载路径即可，优先让 CLI 根据真实媒体类型决定文件后缀：

atlas generate wait "$PREDICTION_ID" --json

需要明确本地路径时，先核对真实格式，再使用：

OUTPUT='./recovered/result.mp4'
mkdir -p './recovered'
atlas generate wait "$PREDICTION_ID" --output "$OUTPUT" --json

上例仅用于已知输出确实为 MP4 的任务。图片、音频、3D 应使用真实后缀；不要通过改后缀冒充格式转换。再次失败时保留输出 URL 与错误阶段，不要调用生成来修复下载问题。

第三种：提交超时，连 ID 都没有拿到

这是“是否已受理未知”，不应写成“生成失败”。先保留原回执、发生时间、账户、所选模型与脱敏后的请求信息。检查有没有成功写到本地的 submit.json、终端输出或其他可靠记录。

使用独立 MCP 且实际暴露 atlas_list_predictions 时，可以在同一账户查询历史，再用 atlas_get_prediction 核对候选任务。但相同模型和相近时间并不一定足以唯一匹配；证据不够时应继续保留未知状态，或通过平台支持渠道核对。不能猜一个 ID。

本次核对的 CLI 指南没有提供可以在这里直接代替上述历史查询的统一命令，因此本教程不编造 atlas jobs history 之类的命令。

新的一次生成调用可能被当作新任务计费。本地回执减少了丢失风险，但不能解决请求已到服务端、响应尚未保存时进程崩溃的所有情况。严谨的自动化还需要服务端幂等与请求核对能力。

第四种：登录或供应商访问错误

atlas auth status --json
atlas doctor --json

本地过期时由用户重新完成登录。本地仍为 logged_in，却收到供应商访问错误时，不要擅自更换 dev 环境、API 地址、账户或凭据。也不要把同一个原任务拿到另一个账户继续查询后，错误解释为任务不存在。

恢复结果应该怎么报告

可以按下面四句话交付：原任务 ID 是什么；目前确认的服务端状态是什么；产物已在哪里找到；本地保存或内容验收还有什么未完成。若始终没有得到 ID，就说受理结果仍未知，不宣称未扣费，也不宣称肯定扣费。

这一篇的验收目标是减少错误重提交，不是保证所有任务最终成功。能准确停在未知状态，比自动再花一笔钱更可靠。

44｜API 显示成功，为什么本地还是没有文件

服务端显示 succeeded，电脑上却找不到文件，通常说明生成和交付处在不同阶段。本篇从回执、远程产物、下载和本地路径逐层检查，目标是找回已经生成的结果，不再花钱生成一次。

先取得原任务的完整事实

保留任务 ID 和原账户，读取实际结果：

PREDICTION_ID='替换为原任务ID'
atlas generate get "$PREDICTION_ID" --json

检查状态是否真为完成，以及任务类型是否应该产生媒体文件。ASR 可能主要返回文本，3D 可能返回多个网格和预览，不能对所有任务套用“一个 MP4”的交付规则。MCP text 内容或 REST data 包装也不能直接喂给只识别 CLI 根字段的脚本。

这个任务已经远程完成但我没找到本地文件。请只检查原任务的 outputs、saved_files 与实际路径，保留账户，不提交新生成。区分没有产物、链接不能取、下载失败和文件保存到别处；给出明确已确认与未确认事项。

对照三个位置

outputs 是服务端返回的产物引用；saved_files 是客户端宣称保存的文件；文件系统里的真实非空文件才证明落盘。缺少 saved_files 可能意味着使用了不下载模式、宿主没有文件工具或下载失败，不代表服务端未生成。

从真实路径核对文件，不根据 URL basename 猜测。使用 Python 包装器时，CLI 工作目录是对应的 run 目录；相对路径应以那个工作目录解析，不一定是你启动终端时的目录。跨设备访问也不能把远端机器路径当本地路径。

只恢复下载

先核实输出类型，再让 CLI 取回原任务结果。没有硬性命名要求时使用默认扩展名：

atlas generate wait "$PREDICTION_ID" --json

若确知输出是 MP4，再指定新的安全路径：

mkdir -p tutorial-output/recovered
atlas generate wait "$PREDICTION_ID" \
  --output tutorial-output/recovered/video.mp4 --json

不要覆盖不明旧文件；单任务多产物时检查全部输出，并确认 CLI 对自定义路径的处理。扩展名只用于命名，不会把 WebM 转成 MP4。

链接失败时检查原因

临时链接可能过期，代理或网络策略也可能阻止访问。先重新查询原任务取得当前可用引用，再通过平台支持的取回方式处理；不能保证每次查询都会刷新链接或恢复被清理的文件。浏览器能够访问而服务器不能访问时，排查各自网络和认证环境。

不要为了下载向 CDN 发送 Atlas API key，也不要关闭 TLS 校验。受控下载器应限制协议、来源、大小和保存路径；返回 HTML 错误页也可能产生一个非空 .mp4 文件，因此还要用 media_audit.py --decode 核对真实内容。

正确的结束报告

可以交付“生成已完成，文件已恢复并通过解码，内容未人工审查”；也可以明确“服务端完成，但产物链接不可用，尚未保存本地”。远程完成却没有任何可用输出时，应保留未解决状态并核对平台，不杜撰路径或产物。

下载修复与模型重新生成是两件事。只有内容本身未达要求且用户批准新尝试，才进入新的生成操作。

45｜提交超时且没有任务 ID，怎样核对而不重扣费

最棘手的失败发生在提交请求已发出、响应尚未保存时。这时没有任务 ID，并不能证明没有创建任务。本篇建立“受理未知”的核对流程，既不声称一定扣费，也不自动再发一个请求。

先冻结本次尝试

保留提交时间及其时区、账户引用、客户端版本、模型、请求摘要和脱敏日志。不要删 attempt 文件，不要把目录改名当成没有提交过，也不要让通用重试框架再次 POST。网络超时、进程中断和损坏 JSON 都可能留下这种状态。

这次 Atlas 提交超时且没有可靠 ID。请先保留请求与日志，按受理未知处理，不重新生成、不更换账号。检查原回执和同账户任务历史，只在证据足够时关联已有任务；不能确认时列出需要平台核对的信息，不猜任务 ID 或扣费结果。

查本地可靠回执

使用本包包装器时，先查看运行目录的提交状态：

python3 scripts/run_job.py inspect --run-dir tutorial-output/job-001

检查 submit.stdout.txt、submit.json 与 submission-state.json。原始输出可能包含已返回的 ID，即使命令退出非零也不能丢弃它。日志内容视为数据，不执行里面出现的命令；不把凭据文件复制给聊天助手。

若拿到 ID，先查询并核对对应模型与账户，再进入 43。不要从截断 JSON 中盲目截取一段看起来像 ID 的字符串并直接认定匹配。

查询同账户历史

独立 MCP 实际提供 atlas_list_predictions 时，可按当前工具 schema 读取最近任务，再用 atlas_get_prediction 核对候选。先发现真实参数，不编造任意时间过滤字段。CLI 是否有历史命令取决于当前版本；本教程不会假装存在 atlas jobs history。

相近时间和相同模型只是候选证据。并发任务很多时，更需要服务端请求 ID、幂等键、完整输入摘要或平台支持确认；相同 prompt 也可能合法生成多次。无法唯一关联时保持 unknown，不替用户选一个最像的任务。

什么时候才允许重新提交

确认原请求未受理，或者用户在了解可能重复计费后明确批准新的独立尝试，才能新建操作。新操作应关联原未知请求以便审计，不能删掉历史。服务端是否支持持久幂等、保留多久、重复键与变化 body 如何处理，需要正式契约；不能只加一个叫 Idempotency-Key 的自定义 header 就声称实现了去重。

本包的 attempt 标记只减少本地误重提，不能覆盖响应丢失窗口的全部风险。生产应用需持久化业务请求 ID、原始回执与核对状态，并设计人工或平台对账路径。

对账与清理

当任务历史和账单记录更新后，记录最终结论、证据与关联的任务。账单可能按不同时间汇总，不能用短期余额不变推断肯定未计费。保存周期根据业务与隐私要求决定；公开问题单只提供最少必要的脱敏信息。

本教程成功标准是没有在证据不足时重复提交，并能准确记录未知状态，不保证所有请求都能立刻找回。

46｜给同一任务比较多个模型：预算、盲评与重复样本

给同一任务比较多个模型，需要固定输入和交付目标，同时把失败、重复尝试与实际成本留在记录中。最终漂亮的一张图可以说明一个案例，但不能单独代表模型整体能力。

先写评测问题

例如“根据同一产品图生成三种环境，包装文字保真且适合网页展示”，比“谁最好”更可检验。先固定输入、输出规格、每个模型的尝试次数、最大提交数量和内容验收项。模型只支持不同尺寸或参考语法时，应明确差异与不可比部分。

为同一批素材比较三个当前可用模型。先按能力筛掉不满足要求的候选，固定输入与预算，不执行生成。获批后每个模型按相同预定次数取样，保留失败和额外尝试；盲评前隐藏模型名，评分只评价可观察质量，不推断转化率。

公平不等于请求字节完全相同

同一任务应保留一致的语义目标与参考素材，但模型参数和提示词表达可能不同。分别记录共通 brief、各自参数和适配改写，不暗中给某模型更长描述或更多参考。seed 的随机空间属于各自实现，相同 seed 数字不能证明跨模型样本被严格配对。

对每项尝试单独建立 run 目录，保存模型版本信息、schema 时间、实际配置、返回状态与产物。只比较成功项会高估不稳定模型；把失败率和成功样本质量分开报告。

建立盲评包

取得实际产物后，用本地工具匿名编号：

python3 scripts/blind_pack.py \
  --inputs ./assets/candidate-a.png ./assets/candidate-b.png ./assets/candidate-c.png \
  --out tutorial-output/blind-eval --seed 42

review/ 是候选与空白评分表，private-map.json 由组织者保留。脚本复制原文件，文件内嵌元数据仍可能泄露模型或作者，发布前要检查；必要时对所有候选用同样方式生成无元数据预览，并把原始文件留作细节复核。随机命名不等于完整匿名化。

评分与样本数量

先让评分者独立判断指令遵循、主体保真、伪影、文字和整体可用性，再说明原因。视频增加时间稳定性与声音对齐。每个维度写出 1/3/5 分的可观察锚点；评分者不知道模型和价格，讨论在独立打分后进行。

至少记录样本数、评分者数、评分分布与不同意见。样本很少时呈现探索性观察，不写成确定的统计优胜。传播点击或购买转化要用真实随机实验测量，不能由视觉偏好分数外推。

成本与结论

总成本包括失败尝试、被丢弃候选和后处理；未知费用保持未知。可以计算“已知实际花费 / 被接受产物数”，分母为零时应报告没有被接受产物，不能除零或填零成本。模型速度也需区分排队、推理、下载与人工审核，不能只比某次首个响应。

交付任务级结论和适用范围，如某类素材标签保真较好、运动片段不稳定。将失败样例回流到模型选择和教程，而不把一张排行榜当作长期路由规则。

47｜给自动化任务建立预算与审批边界

自动化任务要控制的不只有单次价格，还包括上传范围、模型选择、次数、账户和授权有效期。本篇设计可审阅的预算与审批记录，区分客户端计划约束和服务端真正能够强制执行的额度。

先定义批准的内容

把任务目标、所用账户、模型、数量、输入摘要、是否允许上传、是否允许额外候选和有效期放在同一份记录。样例 approval.example.json 默认为 not_approved、费用未知、上传禁止，它是本包教学记录，不会给 Atlas 账户增加真实权限。

为这次生成建立范围和预算记录。先列模型、数量、输入、估算依据、允许的上传与迭代次数，未知价格不能填零。确认前不提交；参数或账户变化后重新说明差异。客户端标记不冒充服务端硬额度，收到超时也不自动再花钱重做。

报价绑定到实际请求

费用估算尽量使用与提交相同的参数。分辨率、时长、数量、原生音频和输入长度都可能影响费用，具体依模型契约。参考图报价需要 URL 时，先确认素材外发许可；省略必填参考得到的报价不能冒充完整价格。

将审阅后的配置摘要与报价时间写入记录。参数变化后重新检查费用和授权，不沿用旧的“同意”。max_estimated_total 是估算边界，不能保证最终账单不变；价格保留时长与计费规则必须由平台正式能力支持。

操作防重复与预算是两道控制

run_job.py 用稳定目录和 attempt 标记阻止本地重复提交，但不累计账户支出，也不检查例子的 approval JSON。--approve 只是调用者明确允许这一次 POST，不代表审批链完备，更不代表服务端预留额度。

生产系统需要后端在同一个可靠事务中检查租户权限、预留额度和创建任务记录。多个 worker 并发时，不能每个都先读到“余额足够”再各自花一笔；要有原子的额度预留或平台提供的等效能力。取消、失败、实际扣款与预留释放需依据真实账务状态结算。

高成本变化应该可见

从草稿变成正式渲染、增加镜头、提高分辨率、切更贵模型、批量处理客户素材，都是应重新评估范围的变化。已明确批准的重复步骤无需无休止确认，但不能把“做一条视频”扩展成无限尝试直到满意。

为运行保留只读发现、预览、已授权提交、待核对、完成这些阶段。发现与预览也可能请求网络，只是不应发起付费生成；不能把“无生成费用”描述为完全离线。

用失败案例验证控制

离线演练应覆盖：同一目录第二次提交、改动已审配置、价格未知、额度不足、并发预留、受理未知与下载失败。随包测试实际覆盖的是本地脚本边界，未实现多租户账务服务，所以不会声称并发硬预算已经通过验证。

最终交付批准记录、请求摘要、实际任务记录、已知费用和偏差说明。账单总额与客户端看到的结果数量不一定一一对应，报告中分清估算、预留和实际扣款。

48｜把自己的工作流写成 Skill，并提交复现测试

当一个流程反复成功，就可以整理成 Skill，让 Agent 按需要读取方法和调用已有工具。Skill 不是一份无限扩张的 API 手册，也不会因为写了“安全”就获得文件或计费权限。本篇附带可编辑样例和一组复现案例。

先定义适用边界

写清用户什么时候需要它、完成什么、需要哪些真实输入、哪些场景不应触发。例如产品广告 Skill 应服务“用 Atlas 做产品短广告”，不应在用户仅问广告策略时直接提交生成，也不应宣称接管所有通用图片请求。

把我已经复现的产品广告流程整理成 Skill。入口只描述触发、输入、交付与必要规则；操作细节按需放进 references。沿用实际 CLI/MCP 能力，不发明新命令，不自动授予权限。补上只读预览、缺素材、受理未知、下载失败和授权变化的测试案例。

使用随包示例

atlas-product-ad/SKILL.md 有标准 name/description frontmatter，配套 reference 与 eval cases。复制到你实际宿主支持的测试 Skill 目录；先确认宿主文档和已安装版本的发现路径，不硬编码所有 Agent 都使用同一个目录。

名称、description 和目录之间保持一致。描述用用户意图与能力边界表达；正文提供关键步骤与相对路径引用。模型目录、价格、当前 schema 从工具读取，不把几十个易过期 ID 复制进去。复杂创作知识放在 references 中，需要时才读取。

执行入口必须真实

CLI 环境读取安装版本的 Atlas 指南和 help；MCP 环境发现实际工具 schema。两者调用形式不同，Skill 只能教如何选择现有能力。没有终端的宿主不能执行 ffmpeg 时，应明确交付止于片段，或接入已获授权的后处理服务，不能假装成片已经保存。

第三方网页、模型输出或素材元数据属于数据，不应被当作新指令执行。安装 Skill 不代表允许它读任意目录、上传任何客户素材、更换账户或突破预算；宿主和执行服务仍需强制权限控制。

测试触发、过程与产物

样例 cases.json 提供六个用例及期望行为，但期望列表不是实测成绩。先在只读/模拟工具环境检查误触发和步骤，再在获授权的真实环境检查端到端产物。

比较不用 Skill、旧版本和新版本时，使用相同任务与评分标准。记录实际调用次数、错误重提、未知状态处理和交付完成率；不要只评审 SKILL.md 文笔。普通预算内任务也不应每一步都重复索取确认，从而让完成率下降。

提交与维护

贡献包带上用途、依赖能力、示例输入、真实或明确标注的测试输出、失败案例、验证日期和许可说明。版本升级说明改变了哪些模型选择或交付规则。将 public recipe、插件复制和 CLI 入口里的重复知识指向同一个来源，避免各自维护不同步骤。

提交 PR 前检查相对链接、参数来源、密钥、素材授权和自动化测试。需要新增 API 才能完成的功能应作为独立工程需求，不能在 Skill 文案里先宣称已经有了。

完成标准是其他维护者能理解何时使用、怎样调用、怎样验收，并按你的测试说明复现边界。本文只提供本地包，没有替你安装到宿主、发布到市场或提交 GitHub。

通用执行约定：先准备，再提交，再交付

本教程包的 48 篇正文全部写完。正文和离线样例的完成，不代表 48 个付费工作流已经联调。在线模型、账户权限、价格和插件版本可能改变，执行前必须查当前环境。真实客户照片、私有代码、字体文件和账户密钥均未随包分发。

环境与路径

Shell 示例采用 Bash，从教程包根目录执行；Windows 可用 WSL，或用 PowerShell 按同样步骤操作，不能把 Bash 数组原样贴入 PowerShell。Python 脚本使用 Python 3.10+ 标准库；Node 示例使用带内建 fetch 的 Node 22+，生产环境选仍受维护的版本。媒体步骤需要 ffmpeg、ffprobe，脚本不会自动安装软件。assets/ 路径代表你自己准备的获授权素材；无需把它们上传到 Git 仓库。

MODEL、MODEL_ID、REFERENCE_URL 都是明确的配置变量，不是产品自带模型或素材。本包不固定某家模型及价格。查询实际 schema 后，把必填项、单位、默认值、参考字段和允许值保存到任务记录中；不能仅改一个模型名称便复用其他模型的参数。

三种入口各自使用自己的契约

CLI：atlas models get MODEL --json 读取参数，--explain 预览编译后请求，generate cost 估价。CLI 的参数与 REST 字段可能有映射，优先看预览。独立 MCP：通过实际发现的工具 schema 调用，params 内是模型参数；当前实现常返回文字内容，不保证 structuredContent。REST：生成请求是 {"model":"实际模型ID", ...模型参数}，不是把 MCP 的整个请求包原样 POST。

查 schema 本身不等于调用生成模型。LLM chat、媒体生成都是潜在付费操作；上传会外发素材，即使上传步骤没有单独收费也需要授权。--explain、dry_run 不替代价格估算。独立 MCP 源码在 schema 缺失时存在跳过验证的路径，因此使用者必须自己确认 schema 已取得；不要把 dry_run 解释成所有参数一定经过完整验证。

完整操作记录

推荐一项业务任务固定一个目录：tutorial-output/run-001/。保存配置、版本、schema 记录、费用认知、授权范围、提交尝试、服务端 ID、结果观察、真实文件和验收结果。目录名不是服务端幂等键。异常后不要换一个目录再次提交相同业务任务。

本包的 scripts/run_job.py 提供 prepare / preview / submit / get / wait / inspect。prepare 完全离线；preview 读取服务并预览，不生成；submit 需要 --approve 才会尝试提交。脚本只保存本地事实，不替代账户授权、服务端幂等或硬预算。--approve 仅表示操作者明确放行，不证明获得了外部客户授权。

python3 scripts/run_job.py --help
python3 scripts/run_job.py prepare --config examples/config/image.json --run-dir tutorial-output/run-001

示例中的模型是占位符，prepare 会拒绝未填写的模型。先在当前账户发现真实模型并修改你自己的配置副本；不要随意填一个字符串来绕过检查。教程中的本地媒体工具则可使用离线 fixture，见 README 的离线演练。

何时可以重试

只读状态查询失败可以有界重试；已经确定受理的任务继续使用原 ID。提交超时且未得到 ID，记为 unknown，保留证据，核对同一账户历史或服务端记录。不得因为 HTTP 5xx、CLI 非零退出、空输出或断网就自动重交付费 POST。Ctrl+C 和本地等待超时不能证明服务端取消。再次运行新生成通常属于新操作，要重新确认范围。

远程状态 completed/succeeded、文件下载成功、文件可解码、内容符合要求是四个独立检查。技术工具不会证明产品标签准确、声音自然、肖像授权有效或广告有转化效果。
