07｜给新网站制作 Hero、功能插图和移动端素材

本次给一个已经有页面结构的网站制作三项素材：桌面 Hero、移动端 Hero、一张功能插图。真正的交付是文件能放进页面且不挡文字，不能只交一张孤立的漂亮图。

从页面槽位开始

打开 examples/briefs/asset-slots.json，把宽高和标题区域改成你的实际设计。示例的 1600×900、900×1200 和 640×480 是练习尺寸，不是某个平台的规定。查看桌面与手机断点，确认图片是 cover、contain 还是背景图；这会影响画面能被裁掉的区域。

先建立一个视觉母版

为虚构开发者工具设计“单一抽象主体、克制材质、统一光线、无文字”的方向。按教程 02 只生成一张参考图，经审核后再做其他素材。移动端可以沿用风格，却常需要单独构图；不要把横版中心裁一下就当作手机版完成。

复制给 Agent

用 Atlas 为现有网站补齐 Hero 和功能插图。先读取我给的页面截图与素材槽位，只生成视觉素材，不修改产品界面或虚构功能。桌面左侧要留标题区，手机上方留文案区。先给一张母版及费用认知，批准后再做另外两项；真实文字由网页渲染。

生成与后处理

按照当前 schema 选择接近目标的画幅，保留母版、提示词与模型记录。精确输出尺寸可在本地完成：

python3 scripts/media_ops.py fit-image --inputs assets/hero-source.png \
  --output tutorial-output/site/hero-desktop.png --width 1600 --height 900 --mode cover
python3 scripts/media_ops.py fit-image --inputs assets/feature-source.png \
  --output tutorial-output/site/feature-a.png --width 640 --height 480 --mode contain

第一条可能裁切，第二条可能补白。源图不足以容纳主体和标题时回到构图，不靠拉伸解决。源文件必须由你提供；这些命令不会生成缺失图片。

放进页面验证

在真实组件里替换图片，分别看桌面、手机、深色/浅色背景。标题不能与主体重叠；按钮应可读；图片加载前后不要造成明显布局跳动。记录导出像素和展示尺寸，压缩后检查边缘、渐变与透明背景；压缩大小上限由项目实际性能目标决定。

验收与恢复

交付三张文件、每张用途、裁切方式、替代文本建议和素材清单。某张需要返工只改对应项，不重新生成整套。字体或标题错误在页面里修，图片里出现多余字母则修画面。完成后可用 manifest.py 对交付目录生成摘要。

依据与复现范围
