# 08｜给技术文章制作封面与 Open Graph 配图

为一篇技术文章制作封面与 Open Graph 图片，先把“文章讲了什么”提炼成视觉关系。不要让图像模型发明跑分、论文结论或作者头像。交付包含无字底图和最终带标题版本，方便改标题时复用。

## 提炼一个画面任务

假设文章主题是“任务中断后如何恢复”，可以画未完成的工作区和被保留的进度；不需要把整篇文字贴到图上。主标题控制为一行或两行，数字与技术名词由作者确认。示例采用 1200×630 作为项目自定输出尺寸；平台预览会改变，发布前用目标平台实际预览核对。

## 复制给 Agent

> 先读我提供的文章正文，提炼一个不夸大结论的视觉主题。用 Atlas 做无文字封面底图，给标题留足空间；标题由排版工具添加，技术名词按原文。先展示方案和费用认知，批准后生成一张。再输出我们选定的 1200×630 版本，不上传文章中未授权的客户信息。

## 制作底图与标题层

按教程 02 生成底图，将构图中的留白与标题摆放联系起来。保存最终接受的原图，再做精确画幅：

```bash
python3 scripts/media_ops.py fit-image --inputs assets/article-background.png \
  --output tutorial-output/article/og-background.png --width 1200 --height 630 --mode cover
```

在你已有的设计工具里放标题、作者署名与项目标识；或使用包内 `examples/layouts/title-card.html`，替换本地图片及文本，在浏览器里检查固定尺寸后导出元素截图。排版模板不包含字体文件，使用你有权使用的本地字体。没有浏览器导出工具时，可以在设计软件中按同样槽位排版。

## 检查缩略图而不是只看大图

把最终图缩到信息流中的实际显示大小，确认标题、主体、留白仍清楚。中文易错字、缩写和版本号应逐字核对。给图起有意义的名字，保留 `background` 和 `final` 两个版本；不要只保存设计软件截图而丢失原文件。

## 交付到网页

站点维护者将 `og:image` 指向部署后可访问的最终图片；`file://` 和本地路径不能作为外部抓取地址。图片可访问不代表平台缓存已刷新，更新后检查实际预览。登录才能访问的素材地址不适合作为公开文章的预览图。

## 验收与常见故障

文章观点、标题与画面没有矛盾；最终尺寸匹配约定；缩小后可读；网页引用的是最终版本。标题变更只更新排版，链接过期只修部署，不能用一次新的模型生成解决这些交付问题。缺少文章正文时先补正文，不凭标题编造技术结论。
