# 04｜面对一大串模型，怎样按输入和用途选择

选择模型先看手里的输入和要交付的东西。一个图片编辑任务即使提示词很短，也不能用只接收文本的模型代替；一个需要透明背景的图标，也不能因为模型画得好看就忽略 alpha 通道。

本次练习为开发者网站制作配图。交付物是一个候选表和一份明确的选择记录；在本篇结束前不产生生成费用。复制 `examples/config/model-selection.json` 作为决策记录。

## 先把需求分成硬约束和偏好

硬约束决定是否可用：输入是文本还是参考图，输出文件类型，允许上传的内容，必须保留什么，输出尺寸能否用于页面。偏好只用于可用模型之间选择：画风、速度、费用、可控性。把“最好”“便宜”换成可解释条件，例如“只需要网页背景，先做一张草稿，不要求图片里写中文”。

## 查询能力，不先提交试试看

```bash
atlas models list --type image --json
atlas models search 'image' --json
MODEL='替换为目录中的真实模型ID'
atlas models get "$MODEL" --json
```

对每个候选记录：是否需要参考图、参数是单图还是数组、输出数量、尺寸选项、可用的报价方法。搜索关键词只帮助发现，不代表搜到的第一个模型就匹配需求。用户点名的模型优先保留，发现能力不符后说明冲突，请用户决定调整要求还是换模型。

## 做一个有排除理由的候选表

| 候选 | 本次输入兼容 | 硬约束通过 | 价格信息 | 决策 |
|---|---|---|---|---|
| 从目录复制 A | 文本可用 | 需核对尺寸 | 估价后填写 | 可进入预览 |
| 从目录复制 B | 必须参考图 | 本次不通过 | 不再查询 | 排除 |
| 从目录复制 C | 文本可用 | 输出类型待确认 | 未知 | 暂停选择 |

这里的 A/B/C 是教学标签，不能当真实模型 ID 使用。缺失值写“未知”，不要填 0。模型数量多时先按模态和输入能力缩小范围，详细读取两三个候选的 schema 即可。

## 用最小样本检验选择

选定后按教程 02 预览和估价，获得授权后生成一张。用实际文件检查构图、留白、缩放可读性。第一张满足要求就停止；失败时记录原因，再判断是提示词、参数还是模型能力问题。不要用一次样本宣称某个模型在所有任务上更好。

## 复制给 Agent

> 用 Atlas 为这个网站选择一个文本生成图片的模型。先列出输入兼容、画幅、数量和费用认知，不生成内容。最多深入比较三个候选，解释排除理由；模型价格未知时保留未知。选定后等我批准一张样图。

## 完成与复用

完成的选择记录应能让另一位同事说明“为什么选它、为什么没选另外两个、哪些能力尚未验证”。保留真实模型 ID、schema 核对时间、请求预览与样本评价；只复用选择方法，不把某个模型写成永久默认冠军。
