# 31｜把视频做超分，并保存前后对照和质量记录

目标是把一段低清视频交给当前可用的增强模型，并保存可公平检查的原始输入、模型输出和评测记录。“输出变成 1080p”只说明尺寸增加，不足以证明细节真实、运动稳定或观感改善。

## 先设计样片，再确认接口

从完整素材中选择静止细节、运动、遮挡、字幕和压缩较重的片段，记录原时码。先用少量代表片段，而非直接提交整部视频。查询账户目录，确认确有视频增强/超分能力，并读取输入、倍率、输出、长度及费用字段。没有相应能力时，可用你获授权的其他超分工具产生结果，再沿用本篇检查流程；不能把文本生视频当成忠实增强。

> 对这段视频做增强测试，先保留源文件并核对当前模型确实支持视频超分。展示输入限制、目标尺寸和费用认知，确认后只处理批准的样片。交付原片、未经再次压缩的模型结果、同时间轴比较与失败记录；不要声称没有原始高清真值也测得了恢复准确率。

## 固定对比条件

保存源编码、分辨率、帧率、裁切范围和是否有原生 HDR 信息。不同候选应使用同一解码后的内容和时段，不得给其中一个额外锐化后再比较。模型内部是否改变帧率或补帧要记录；即使输出帧数接近，也需检查起始偏移和尾部截断。

```bash
python3 scripts/media_audit.py ./assets/source.mp4 --decode
python3 scripts/media_audit.py ./assets/upscaled.mp4 --decode
```

元数据不是质量分数。先对齐同一事件的时间和裁切，再生成方便观看的比较预览：

```bash
python3 scripts/media_ops.py side-by-side \
  --inputs ./assets/source.mp4 ./assets/upscaled.mp4 \
  --width 640 --height 360 --fps 30 \
  --output tutorial-output/upscale-comparison.mp4
```

这个预览会缩放并重新编码，不能替代原文件的 100% 像素细节检查；脚本也不会自动寻找时间偏移。`--fps 30` 只规范预览播放，不用于修改原始评测基准。

## 看空间，也看时间

检查细线与文字是否变形、边缘是否有光晕、脸部是否生成陌生细节、纹理是否反复闪动。连续播放相机移动和遮挡出现的位置，首帧好看不代表整段稳定。把失败归到具体场景，而非只给一个没有解释的总分。

没有真实高清参考时，PSNR/SSIM 不能直接被称为“恢复真值准确度”。有严格配对的高清源时，可以构造清楚记录退化过程的样本，算全参考指标；真实低清材料另做盲评和时序检查，二者分开报告。普通插值可作为本地对照，但不是高清真值。

最终记录各样本技术规格、实际耗费（已知才填）、人工评价、错误与重复尝试。使用 [46](46-model-evaluation.md) 扩展多模型盲评；始终保留失败样本，不能只展示最成功的一段。
