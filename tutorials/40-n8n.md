# 40｜把 n8n 接成内容生产流程

n8n 可以把素材输入、Atlas 生成和后续分发连起来。本教程先做一条手动触发的最小流程，区分提交节点与状态节点，再增加业务持久化。已有社区节点时优先检查实际版本，不按照旧截图猜参数。

## 安装与最小导入

在你获授权管理的 n8n 环境安装 `n8n-nodes-atlascloud` 社区包，确认实例允许该包以及当前节点版本。使用 Atlas Cloud API credential 保存密钥，不写在 Code 节点、HTTP body 或可公开导出的 JSON 中。

导入 [n8n-submit-poll.json](../examples/workflows/n8n-submit-poll.json)。它按照实际公开节点结构编写，包含 Manual Trigger、Atlas Task Submit、Atlas Task Status；没有有效凭据，模型是不可用占位，必须从当前节点下拉框重新选择并补上必填字段。未激活工作流不代表点击 Test 不收费。

> 帮我接通 n8n 的 Atlas 内容流程，先只检查节点、凭据引用和参数，不执行生成。确认后一次提交，保存实际 prediction ID，再由 Status 节点查询；下载或发布失败不重新执行 Submit。任何对外发布先经过人工验收。

## 配置提交与查询

Task Submit 选择当前实际 Category、Model 和 `Submit Only`。Task Status 的公开示例从 `{{$json.prediction_id}}` 读取 ID；你仍要观察当前节点真实输出，因为不同包版本可能改变形状。最小示例中的等待时间字段单位由该节点界面定义，不能根据数字 15 猜是十五秒还是十五分钟。

先在明确批准的单项素材上运行，确认 ID 已持久保存、Status 返回实际状态。状态未完成时只继续查询。设置节点重试时不要把所有错误统一设为“重跑提交”，尤其是请求超时或响应丢失。

## 生产使用要补外部状态表

最小 JSON 为教学图，没有数据库账本。要做批量业务，先用可靠存储保存业务 item ID、账户、请求摘要、attempt 状态和 prediction ID，再分支到轮询与下载。执行记录保留时间可能有限，不能把 n8n 的一次运行日志当作永久账本。

提交节点发请求前写 attempt，受理后更新 ID；GET/状态节点出错可以恢复原查询。对未知受理项保留人工核对队列，不能通过清空状态重新触发。

## 下载、字幕与发布

只有已确认成功并拿到目标产物时，才调用 HTTP Request 下载文件。下载 URL 不应携带 Atlas 的 Authorization；按允许的来源和体积限制下载，不让用户任意提供的 URL 访问内网。进入下一步时检查 binary 数据是否确实存在，而不是只传递一个过期链接。

有需要时把成片交给专门的受控后处理服务，再执行 [35](35-delivery-audit.md) 的检查与人工批准。自动发社媒、邮件或 CMS 是额外动作，应有明确发布授权，不能由“帮我生成素材”推断。

## 别把 Wait webhook 当成 Atlas 回调

n8n Wait 节点能够按时间或自身 webhook 恢复，但这不证明 Atlas 生成接口支持回调参数。没有明确平台契约时走状态查询；如需 webhook 通知，由你的服务在核实 Atlas 任务后发给自己的 n8n 流程，详见 [42](42-polling-webhook.md)。

本包仅静态检查示例 JSON；发布前仍需在目标实例验证节点导入、凭据和结果形状。
