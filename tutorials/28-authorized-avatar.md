# 28｜用获授权肖像与声音制作讲解视频

本篇制作经过授权的讲解视频。输入是一张有使用权的肖像、批准的口播稿，以及已获授权或标准合成声音。目标是完成可追溯的合成讲解片，不把真人身份和声音当成随手可下载的素材。

## 在生成前检查授权范围

记录肖像来源、被表现者同意的用途、声音来源、发布渠道、授权期限和是否允许修改文稿。授权文件可以存于受控系统，本地清单只保存引用编号，不必把签字或证件交给模型。标准 TTS 与声音克隆应区分；本教程默认使用标准声音，不教授仿冒未经同意的真人。

> 用我明确授权的肖像与文稿做讲解视频，使用标准合成声音。先检查当前 talking-avatar/lipsync 模型的输入与时长限制，解释会上传什么、如何标识合成内容及费用认知。没有所需授权或能力时停止。确认后只执行获批的文稿，不让人物说额外的话，交付完整视频和口型、声音、披露检查结果。

## 先音频，后视频，保存两份回执

审定口播稿后按 [25](25-voiceover.md) 生成声音，完整听检。不要先让头像模型说完再修改文本，因为一次读音错误会拖着视频一起重做。音频通过后，记录真实时长，再选择支持肖像+音频输入的模型。

通过 `atlas_list_models` 查询 Video 类候选，再读取 `atlas_get_model_info`。确认工具实际需要的字段：图像可能是单 URL，声音可能是音频 URL，部分模型还要求视频模板。仅知道模型名字包含 avatar 不足以推断参数。若选择 `atlas_quick_generate`，先确认模型解析唯一且输入映射正确；面向发布任务优先使用已确定模型的明确请求。

取得上传许可后，把肖像和声音变为当前模型支持的输入。保留素材校验值、具体模型 ID 和两次任务 ID。不要将真实本地文件名放进 prompt 后当作已经上传。

## 视频验收要看连续段落

检查眼睛、牙齿、嘴部边缘、头颈连接、手部和背景的连续运动。听声音是否完整，口型有没有持续偏移；不能只凭首帧肖像接近就判定合格。对于镜头转动很大或嘴部被遮挡的输入，先换用获授权且更合适的照片，不应擅自抓取另一张网络肖像。

```bash
python3 scripts/media_audit.py ./assets/avatar-final.mp4 --require-audio --decode
```

实际文件路径由回执确定。解码检查不能测量口型同步，仍需观看和听检。若只声音坏了，先核对原音频；若音频正确而口型错位，问题在视频阶段，不必重新生成 TTS。

## 发布与交付

按照你的使用场景和适用要求清楚披露这是合成视频，避免暗示真人参加录制或亲自发表了未批准的讲话。身份与授权不能仅靠一个 `consent=true` 字段获得证明。交付视频、批准稿、合成说明、素材授权引用、模型/任务记录和人工检查结果；原始肖像与授权文件保持受控，不放进公开示例仓库。
